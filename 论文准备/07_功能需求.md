# 07 功能需求

> **一句话**：删除有**两条路线**——静态死组件（零成本，当地基）和动态无用组件（要实验，是核心贡献）。
> 只做前者，论文不成立。

---

## 一、两条删除路线

| | **A：静态死组件** | **B：动态无用组件** |
|---|---|---|
| 是什么 | **从未被执行**的组件 | 执行过，但**删了分数不掉** |
| 怎么找 | AST 引用分析 + 运行时覆盖 | **逐段删掉，真跑一遍** |
| 成本 | 极低（扫一次） | 高（组件数 × n × 题数） |
| 别人做过吗 | 编译器早在做（dead code elimination） | **没人做过** |
| 论文位置 | **第 0 号实验（地基）** | **核心贡献** |
| 风险 | 被说成"这是 linter 的活" | 成本高、n 不够就测不出来 |

**关系**：A 先做，因为零风险、能快速建立"删除不掉分"的信任；B 才是论文的立身之本。

---

## 二、要建的功能（F1–F10）

### P0：不做就没法开跑

| 编号 | 功能 | 什么算做完 |
|---|---|---|
| **F1** | 多 agent 适配层 | 6 个 agent 至少 2 个能一条命令切换 |
| **F2** | H0 基线复现 | 同命令 3 次，极差 ≤ δ |
| **F3** | 记录 schema | 任一历史结果能追到命令 + commit |

### P1：核心创新

| 编号 | 功能 | 什么算做完 |
|---|---|---|
| **F4** | **组件级 K** | 输出"组件 → K"分解表（六类组件） |
| **F5** | **静态死组件检测** | 每条附证据（无引用点 / 无调用记录） |
| **F6** | **反事实删测** | 逐段三态表：保留 / 删除 / **不可判** |
| **F7** | **防御式白名单** | 开启后删除建议数明显下降（有前后对比） |

### P2：让论文站得住

| 编号 | 功能 | 什么算做完 |
|---|---|---|
| **F8** | 双池隔离 | 演化进程读量外池**直接报错** |
| **F9** | 判定器 | 构造"S 涨、K 大涨"必须被拒 |
| **F10** | 统计报告 | 配对 bootstrap 100,000 次 + ≥2 次独立演化 |

---

## 三、以后测什么（T1–T8）

| 阶段 | 测什么 | 成本 |
|---|---|---|
| **T1** | 组件级 K 的分布（不跑模型） | 极低 |
| **T2** | 删静态死组件后 S 不变 | 低 |
| **T3** | 动态删测，先打**分类集** | 低（分钟级） |
| **T4** | 删测搬到 TB2（先抽 20 题） | 高 |
| **T5** | 主结果：TB2 2.0 + 2.1 | 高 |
| **T6** | SWE-bench Verified 500 | 很高 |
| **T7** | 换 GLM-5.2 迁移 | 中 |
| **T8** | 演化池 vs 量外池 gap | 中 |

---

## 四、删测成本必须先算

单次 ≈ **组件数 × n × 题数**。

| 场景 | 组件 | n | 题 | rollout 总数 |
|---|---|---|---|---|
| 分类 harness | ~8 | 10 | 200 | **1.6 万** |
| TB2 抽样 | ~15 | 10 | 20 | **3 千** |
| TB2 全量 | ~15 | 10 | 89 | **1.3 万** |

→ **先做分类集，TB2 先抽样，全量留最后。**

---

## 五、排期

```
F1+F2+F3 → F4+F5 → T1+T2 → F6+F7 → T3 → T4(抽样) → F8+F9+F10 → T5→T8
```

F4/F5 排在不烧模型的位置：一两天能出中间结果；F6 一开跑就是几万次 rollout。

---

## 六、三个风险

| 风险 | 应对 |
|---|---|
| K 口径一变，之前数据全废 | F4 必须在任何正式实验前定稿 |
| A 被说成"linter 的活" | 明确定位为地基，主贡献放 B |
| n 不足会误判"没用" | 表脚注写清：**n=10 只能检测 ≥10% 的失败率** |

---

## 只记一件事

**"没测出影响"不等于"没用"——这句话要印在删测表的脚注上。**
