# 10 K 的度量标准

> **一句话**：K 不该自创。代码有 50 年的标准度量（Halstead / 圈复杂度 / SLOC），
> 文本有压缩率标准（LLMLingua 定义的 τ）。**我们只是把成熟度量搬到 harness 上。**

---

## 一、先分清两个词

| 概念 | 是什么 | 例子 |
|---|---|---|
| **数据标准** | 规定数据长什么样 | Parquet、HF task 格式 |
| **度量** | 规定怎么量一个属性 | 圈复杂度、LOC、token 数 |

**K 是度量，不是数据标准。** 所以要问的不是"有没有公用格式"，而是"这个量法有没有公认定义"——**有**。

---

## 二、代码类：业界标准（有 ISO 背书）

| 度量 | 量什么 | 工具 |
|---|---|---|
| **LOC / SLOC** | 体量 | `cloc`、`radon raw` |
| **圈复杂度 CC** | 控制流复杂（要测多少路径），>10 算高 | `radon cc` |
| **Halstead 体积 V** | **信息量**（把代码当语言看） | `radon hal` |
| **可维护性指数 MI** | 维护难度（V + CC + 体量的合成） | Visual Studio 内置 |
| **认知复杂度** | 嵌套有多绕 | SonarQube |
| **NCD** | gzip 压缩距离（无参数） | 任何 gzip |

依据：**ISO/IEC 25010** 把"可维护性"列为质量特性，其子特性就是靠这些结构度量量化的。

> 老师报告 6.1 节原文提到"K(h) **或圈复杂度等复杂度惩罚项**"——说明他设想的就是标准度量。

---

## 三、文本类：也有标准（我一开始说"没有"是错的）

### 冗余度：压缩率

| 项 | 定义 |
|---|---|
| **压缩率 τ** | `τ = L̃ / L`（压缩后 token / 原 token） |
| 压缩比 | `1/τ`，工程上写 "3.5x" |
| 计数口径 | tiktoken（GPT-3.5 编码器） |

出处：**LLMLingua**（arXiv 2310.05736）§3。

**它恰好解决"同一句重复三遍"**——重复内容压缩率天然高，而 token 数完全看不出。

⚠️ 但 LLMLingua 是**有损**且依赖小模型，只适合当交叉校验。
**主口径用 `gzip` 压缩率**：无模型、任何人可复算。

### 可读性：Flesch 系（**只适用英文**）

Flesch Reading Ease（1948）、Flesch-Kincaid（1975）、Gunning Fog（1952）、SMOG（1969），
工具 `textdescriptives` 一次全给。

⚠️ **致命限制**：依赖音节数 / 字母数 / 词数，**中文没有对应物**。
我们的提示词大量是中文，硬套会得到无意义的数。

---

## 四、我们的口径

| 组件类型 | 主度量 | 辅度量 | 排除 |
|---|---|---|---|
| **代码**（工具、middleware、钩子） | Halstead V | 圈复杂度 + SLOC | — |
| **中文提示词 / skill** | token 数 | **gzip 压缩率** | Flesch 系 |
| **英文提示词** | token 数 | gzip + Flesch-Kincaid | — |
| **配置** | 字段数 + 序列化 token | — | — |
| **编排** | 节点数 + 边数 | — | — |

**不合成一个标量**：代码与文本的"一行"信息量不同，硬加权会被套利。

---

## 五、对标论文都在量什么（**没有一篇用标准度量**）

| 论文 | 它叫什么 | 实际量什么 |
|---|---|---|
| RRSI | "Complexity-aware acceptance" | **policy token 成本**（原话：*as a measurable proxy*） |
| HarnessPro | 成本 | 美元 / token |
| Meta-Harness | 上下文成本 | context token |
| AHE | tokens/trial | prompt+completion token |
| HarnessDev | 效率 | execution-token（LOC 只作描述变量） |

**这带来一个必答题**：审稿人会问"为什么不直接用运行成本？"

**回答**：
> C 高可以靠更强模型、缓存、短上下文来降；K 高只能靠"少写、少绕、少冗余"来降。
> **K 是交付物本身的属性，与跑多少次无关。**

---

## 六、工具与版本必须钉死

| 用途 | 工具 |
|---|---|
| Halstead / CC / LOC | **`radon`**（`hal` / `cc` / `raw`） |
| 跨语言 LOC | **`cloc`** |
| 文本 token | **`tiktoken`**（写清编码器名） |
| 压缩率 | **`gzip -9`** |

要冻结六项：radon 版本、cloc 版本、tokenizer 名、压缩级别、注释识别规则、组件切分规则。
**缺一项别人就复算不出来。**

## 只记一件事

**K 的每一半都有别人定义过；我们要证明的不是"K 新"，而是"把 K 当接受准则"这件事新。**
