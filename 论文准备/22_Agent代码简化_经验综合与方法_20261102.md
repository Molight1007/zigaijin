# 从 14 篇论文提炼：agent 代码简化的经验与方法

2026-11-02 ｜ 信源：`21_Agent代码压缩_论文精读_20261102.md` 的 14 篇（本地 PDF 全在 `信息来源/papers/`）

> **这份文档不是摘要集。** 摘要在 `21_` 里，这里只做两件摘要做不了的事：
> ① 把**多篇独立论文重复命中的结论**挑出来重点分析——重复才是可靠信号；
> ② 把**只有某一篇才有的东西**单独列出来——独有才是引用价值。
> 最后落到"我们的 agent 代码该怎么简"。

---

## 0. 为什么"重复"值得单独分析

一篇论文说"噪声很大"，可能只是它的 setting 特殊。
**五个不同机构、五套不同 benchmark、彼此不引用**，都说"不重复测就没法判"——这就是领域事实了。

所以下面每条经验都标三件事：
- **命中几篇**（几篇独立做出这个观察）
- **独立吗**（不同机构 / 不同基准 / 互不引用 → 才算独立复现）
- **代价是什么**（不遵守会怎样，用数字说）

本篇判断独立性的口径：**机构不同 + 基准不同 + 不互为对照** 三条都满足才算独立。

# 第一部分　重复的经验（重点）

## 经验 1｜冗余是普遍且巨大的 ★★★★★（5 篇独立）

**命中**：SHarP、Cortex、SlopCodeBench、HarnessPro、RRSI
**独立**：UCSB+MIT-IBM+Adobe / 独立研究者 / UW-Madison+MIT / 清华+Z.AI / Google Cloud —— 五家互不引用，五个不同基准

| 谁 | 怎么量出来的 | 结论 |
|---|---|---|
| **SHarP** | 4 个 harness 逐模块消融 | OpenHands **27 个模块里能剪掉 24 个**，分数还从 29.44% 涨到 35.00% |
| **SlopCodeBench** | 15 个 agent × 473 个开源仓库对照 | agent 代码比人**啰嗦 2.3×、侵蚀 2.0×** |
| **Cortex** | Claude Code 的 skills/rules 增删都要回放 | 原话：harness "像文档一样长起来"，"很少被测量" |
| **HarnessPro** | RSI 的动机陈述 | 性能提升"often at the cost of higher token consumption and increased latency" |
| **RRSI** | 三类失败模式归纳 | "复杂度累积"是其中之一，特征是**单调不减、路径依赖、非结构化** |

### 为什么这条重要

它把"要不要做压缩"这个问题**从判断题变成了工程题**。不需要再论证"可能存在冗余"——已经被五家量过了。剩下的是"怎么判该删哪个"。

### 对我们的后果

**"harness 有大量冗余"不能再当卖点。** 这句话现在写进 intro 只会被问"那 SHarP 不是已经做了吗"。
我们要接的是**后半句**：SHarP 证明了冗余存在，但它用的是 token 口径、事后一次性剪、粒度是整块开关——**判据和时机都还没人做**。

## 经验 2｜一次测量不算数，噪声比想象的大 ★★★★★（5 篇独立）

**命中**：Cortex、SHarP、RRSI、Growing Harness、SlopCodeBench
**独立**：五个机构，五套基准

| 谁 | 量化出来的噪声 | 怎么处理的 |
|---|---|---|
| **Cortex** | 同一 harness、同一批任务、分两批 rollout，差 **−3.3pp，95% CI [−7.3, 0]** | 每任务跑 m=2 次，门 4 要求 `k·N ≥ m`，"一次赢是抛硬币" |
| **SHarP** | 未直接报，但每档配置跑 **3 次**取平均 | 模块显著性用**配对 t 检验**，p≤0.05 才算"关键" |
| **RRSI** | **分域实测**：TB2 3/178=**0.017**、Harvey 60/14,100=**0.004**、EngDesign 5/244=**0.020** | δ 不手工设定，用未改动基座重复评估取经验分布 |
| **Growing Harness** | 3 次独立评估 + cluster bootstrap，50 题规模下 **CI 半宽 11–13pp** | 所有表都报 `均值 ± 半宽` |
| **SlopCodeBench** | 质量速度 **1.3pp/检查点** | Table 1 全部带 ± |

### 为什么这条是"最该抄"的一条

**它的形式最简单**：`S ≥ S* − δ`，δ 是量出来的。
**它的后果最严重**：不测 δ，你无法区分"改进了"和"刚好抖了一下"。

Cortex 那句原话值得抄进论文：
> "一个 −3.3 点的差异，**只看一次会被当成效应**。"

### 对我们的后果

我们现在 n=3~13，**根本没到能判任何东西的规模**。这一条不是"要补"，是"不补则所有结论都不成立"。§7 给了具体算法。

## 经验 3｜判断不能替代测量 ★★★★★（5 篇正面 + 1 篇反例）

**命中正面**：SHarP、Cortex、HarnessMinimizer、CodeTaste、REFINE
**命中反面**：RRSI（它的剪枝是启发式，删完不跑）

| 谁 | 它怎么"测" | 结果 |
|---|---|---|
| **SHarP** | 方法本身**就是**单模块消融 | 唯一敢说"剪了 24 个还涨分"的原因 |
| **Cortex** | 加要测、**删也要测**（`/prune` 同一套回放） | 敢说"模型没用过的文本既不新增也不删除" |
| **HarnessMinimizer** | oracle 必须真跑（还崩不崩） | 才敢把 1352 token 压到 143–263 |
| **CodeTaste** | 让模型**自己找**该重构哪 | **只有 7.9%** 对（写清楚要改什么时有 69.6%） |
| **REFINE** | 五段式流水线 + 保持性检查 | 坏味道降 68–73%，但 **assert 只保住 57.1%** |
| **RRSI（反例）** | 收益窗口 `n_prune=4` 挂"待删"标签，**不验证删了掉不掉分** | 这是它和我们的关键分野 |

### 为什么这条最"反直觉"

因为**看起来最省事的做法恰好最不可靠**：
- "让模型自己判断哪里冗余" → **7.9%**
- "加几道静态检查" → assert 仍丢 **42.9%**
- "按规则挂标签"（RRSI）→ 没人验证过

而所有真的量了的，全都活下来了。

### 对我们的后果

**"删完必须真跑"不是纪律，是方法的核心。** 我们的 detector 现在能找出 7 类可删项（死函数、未用导入、恒假条件、不可达、重复分支、空包装、重复块）——**这 7 类都还只是"候选"，不是"结论"**。
这个区分必须在代码和论文里同时说清：`detector` 回答"哪里可能能删"，`gate` 回答"删了之后真的没坏吗"。

## 经验 4｜"行为等价"没人敢宣称，只能分层逼近 ★★★★★（7 篇，零例外）

**命中**：REFINE、HarnessMinimizer、Cortex、SHarP、CodeTaste、ACE、LLMLingua
**没有一篇说"我保证了行为等价"。**

| 谁 | 它的"等价"是什么 | 强度 | 它自己怎么说 |
|---|---|---|---|
| **HarnessMinimizer** | 还崩不崩（二值、确定） | **最强** | 但只适用于"崩溃复现"这一种性质 |
| **Cortex** | 每道题都没明显变差（多次回放） | 强 | 统计口径，不是证明 |
| **SHarP** | 整体分数可比（3 次平均） | 中 | 允许个别题变差 |
| **CodeTaste** | 测试套件不出现重大回归 | 中 | 取决于测试覆盖 |
| **REFINE** | 静态保持代理 88% + assert 57.1% | **弱** | 原话："**是风险证据，不是行为等价性的证明**" |
| **ACE / ACON** | 任务分不显著降 | 中 | 统计口径 |
| **LLMLingua** | 压根不提等价 | — | 压缩后可以不合语法，模型照样懂 |

### 这条的真正含义

**不是"大家都做不到"，而是"这个领域已经默认：不能说等价，只能说没观测到退化"。**

这给了我们一个**免费的合法性**：只要我们把话说成"在 X 测试集、k 次重复、四道门都过的情况下未观测到行为变化"，就站得住，不需要证明等价。

### 对我们的后果

**现在我们的口径是全场最弱的一档**（"gzip/行数变短就算改进"）。这不是丑，是**话没说全**。补法见 §4 的四道门。
另外把 REFINE 那句原话引进去，比我们自己解释一百字有用。

## 经验 5｜膨胀的主要伤害是"用不上"，不是"贵" ★★★★（4 篇独立）

**命中**：Cortex、SlopCodeBench、ACON、Growing Harness

| 谁 | 证据 |
|---|---|
| **Cortex** | 同样内容的 skills：**跟着任务涉及的文件一起给**就有用；**每轮都摆在面前**反而"很少被打开" |
| **SlopCodeBench** | 侵蚀的定义就是"复杂度向少数函数集中"→ **代码过得了测试，但越来越难扩展** |
| **ACON** | 小模型被长上下文干扰，压完反而 **+46%**（不是省出来的，是"不干扰"出来的） |
| **Growing Harness** | Tool-Calling 用 4B 模型在 WebArena 掉到 **6.7%**；把控制搬进代码后同模型回到 **45.3%** |

### 为什么这条改变了"压缩"的定义

如果伤害主要是钱，那"压缩"是个**成本优化**问题。
如果伤害主要是"用不上 / 被干扰 / 难扩展"，那"压缩"是个**能力问题**。

四篇的证据都指向后者。

### 对我们的后果

**K 降低的收益应该记在"可归因 / 可检索 / 可扩展"账上，不是"省钱"账上。**
这也正好接上 HarnessMinimizer 那条：精简后 LLM 归因准确率 **28% → 44–51%**。

---

## 经验 6｜"省钱"是伪收益 ★★★★（3 篇 + 1 反例）

**命中**：ACON、SlopCodeBench、ACE
**反例**：Growing Harness（它的钱是真省的，但那是"把控制搬进代码"省的，不是"压缩"省的）

| 谁 | 账 |
|---|---|
| **ACON** | 压历史：成本 **−13.9%**，延迟 **+19.7%**；压观察：成本 **−17.8%**，延迟 **+39.2%** |
| **SlopCodeBench** | 加"写干净点"的提示：初始侵蚀 −62.3%，但**每检查点成本 +12.1%**，恶化速率不变 |
| **ACE** | 压到 122 token 后准确率 57.1%——**比完全不压（63.7%）还差** |

### 对我们的后果

**不能卖"省成本"。** 审稿人拿 ACON 表 4 一算就穿。
能卖的是：结构可审计（K 可复算）、失败可归因（28%→44–51%）、系统可扩展（SlopCodeBench 的侵蚀定义）。

## 经验 7｜删不是单调的：删了可能更贵、更脆 ★★★（2 篇，但极关键）

**命中**：SHarP、REFINE

**SHarP 的两处实证**（这是全文最容易被忽略的两段）：
1. 删掉"帮助 agent 识别任务完成并终止"的模块 → agent 在任务完成后**继续调用模型**，**token 反而上升**
2. PaperQA2 剪 15 个模块的配置、JIT agentfold 全剪的配置，**都比全量 harness 更贵**
3. 结论原话："剪枝能减少冗余动作和输入上下文，但**也可能删掉帮助 agent 高效完成任务的功能**"

**REFINE 的实证**：42.9% 的文件在重构后**丢了关键 `assert` / `fail` 调用**——分数不掉，问题在下一个版本才炸。

### 为什么这条必须重点讲

因为它**直接否掉了"删越多越好"这个默认假设**。而我们的 K 惩罚如果不带门，就会**系统性奖励**这条错误方向——因为防御式代码、终止检测、错误处理，在静态度量下全是"复杂度"。

### 对我们的后果

必须加一道**非单调门**：删完之后，**单个任务的 token 成本不得上升**；总量也不得上升。
现在没有这道门。这是设计缺口，不是实现细节。

---

## 经验 8｜长也不单调：有些代码该长 ★★★（2 篇）

**命中**：Growing Harness、SHarP（间接）

**Growing Harness**：把重复的控制判断编译成代码 → LLM 调用 **−76%~−92%**，成本 **−74.4%~−98.6%**，4B 模型从 6.7% 回到 45.3%。
它证明了：**"代码变多"和"变好"可以同时发生。**

**SHarP 间接支持**：它剪掉"任务完成检测"后成本反升——说明有些"看起来是冗余"的模块其实在承担控制。

### 对我们的后果

论文里必须显式回答这个问题：
> "Growing Harness 证明代码越长成本越低，你为什么反着走？"

**答法**：区分"承载控制流的代码"（该长，被摊销的确定性逻辑）和"不承载控制的代码"（该删，没被测过的冗余）。
**而且这个区分不能只写在论文里，要能算出来**——见 §4 第 0 步"触达普查"，触达次数为 0 的模块既不是控制也不被需要。

---

## 经验 9｜先验"触达"，再谈"有用" ★★★（2 篇强 + 1 篇弱）

**命中**：Cortex（强）、SHarP（弱，靠消融隐含）、HarnessMinimizer（弱，另一层意思）

**Cortex 的两个设计是这条的完整形态**：
1. **门 5：`f ≥ 1`**——"一个从没被触发过的候选，不能算有功"
2. **只给被加载过的任务打分**——一条 rule 在 26 道题里只有 6 道真进了上下文，**就只算这 6 道**

**HarnessMinimizer 是另一个层次**：它记录并重放输入值，确保"删掉读输入的语句后，存活调用拿到的值不变"——本质也是"先搞清楚什么真的被用了"。

### 为什么这条容易被忽略

因为"这段代码有没有用"这个问题，**看起来可以静态回答**（有引用就有用）。但真实情况是：
- 有引用 ≠ 被执行（可能是走不到的分支）
- 被执行 ≠ 影响结果（可能算完就扔）
- 影响结果 ≠ 在评测里被触发（可能只在长尾触发）

Cortex 的门 5 卡在**第二层**，曝光限定卡在**第三层**。这两层我们现在都没有。

### 对我们的后果

**这是收益最高、风险最低的一步，而我们完全没做。**
做法见 §4 第 0 步。

## 独有经验里，最该立刻拿走的四条

# 第四部分　方法：五步删减 + 四道门 + 三条纪律

> 这是把上面 9 条重复经验 + 14 条独有经验压成可执行流程。
> 排序原则：**先做零风险高收益的，后做高风险低收益的。**

## 五步删减（严格按顺序）

### 第 0 步｜触达普查（不改任何代码）

**做什么**：跑一遍现有实验，统计每个"可删单元"（函数 / 分支 / 环境变量 / 提示段落 / 工具定义）：
- 被调用了多少次
- 被调用时是否影响了最终输出
- 是否在评测任务里被触发过

**产出**：一张三列表——`单元 | 触达次数 | 触达的任务数`

**为什么排第一**：
- **零风险**（不改代码，只观测）
- **收益最大**（SHarP：27 个模块里 24 个可剪）
- **直接回答分歧 4**（不需要模型判断，也不需要昂贵消融）

**证据支撑**：经验 9（Cortex 门 5 + 曝光限定）、经验 1（SHarP 的冗余率）、经验 8（区分"控制代码"和"冗余代码"）

### 第 1 步｜删"零触达"

**判据**：触达次数 = 0 且在 N 次实验中从未影响输出。

**风险**：**最低**。但仍然可能"只在长尾触发"——所以判据要写"在**当前评测集**上零触达"，不是"永远没用"。

**证据**：Cortex 门 5；SHarP 剪掉 24/27。

### 第 2 步｜删"有触达、零贡献"

**判据**：单模块消融后，分数差落在 δ 内，且 token 成本不升。

**风险**：中。必须带**非单调门**（经验 7）。

**证据**：SHarP 的效率显著性；但注意它自己也踩过"删了更贵"的坑。

### 第 3 步｜并"重复表述"

**判据**：语义相同的规则合并成一条定义，其余处引用。

**风险**：中高。**经验 4 说没人能证明等价**，所以必须靠测试而非判断。

**证据**：SlopCodeBench 的 verbosity（结构性重复占 75.5% 的轨迹在上升）；我们 detector 里的 `_find_duplicate_branches` / `_find_duplicate_blocks`。

### 第 4 步｜等价改写

**判据**：行为不变但更短的表示。

**风险**：**最高**。CodeTaste 的 7.9% 说的就是这一步。

**证据**：Perses（语法引导 + oracle）；LLMLingua（token 级删减）

**结论**：**这一步应该是收益放大器，不是默认动作。** 前三步没做干净之前不要碰。

## 四道门（每一处删除都要过）

```
候选删除 ──► 门0 触达 ──► 门1 噪声 ──► 门2 分层等价 ──► 门3 非单调 ──► 采纳
              │            │             │              │
              └ 没触发过    └ 差在δ内     └ 四层全过     └ token 没升
                 → 不算有功    → 不算赢      → 才算没坏     → 才算划算
```

| 门 | 判据 | 来源 | 我们现在有吗 |
|---|---|---|---|
| **门 0 触达** | `f ≥ 1`：该单元在评测中被触发过 | Cortex 门 5 | ❌ |
| **门 1 噪声** | `S ≥ S* − δ`，δ 实测，k 次取**最差** | RRSI + Cortex | ⚠️ 有 `S*−δ` 概念，但 δ 未测、k=1 |
| **门 2 分层等价** | ① 能 import/编译 ② 测试全过 ③ 分数不跌出 δ ④ AST 白名单未触碰 | REFINE + Perses | ⚠️ 有三重门，缺第 ④ 层 |
| **门 3 非单调** | 删除后**单任务与总 token 均不上升** | SHarP 的反例 | ❌ |

**门 2 的第 ④ 层要展开成 REFINE 那五类**（这是唯一一份具体清单）：

| 保护类别 | REFINE 的实测保留率 | 我们的处理 |
|---|---|---|
| 公开方法/函数签名 | 86.2%–94.2% | **禁止改动** |
| 异常处理结构 | 92.4%–96.2% | **禁止删除** |
| 框架契约（装饰器/钩子） | 90.4%–94.4% | **禁止删除** |
| 条件结构 | 86.0%–90.0% | 需逐条说明理由 |
| **关键 assert / fail 调用** | **57.1%** | **AST 层硬保护，永不可删** |

最后一行是重点：**连强模型 + 五段流水线都只能保住 57.1%**。所以我们不能靠"提示它别删"，必须在 AST 遍历时就跳过这些节点。

## 三条纪律

### 纪律 1｜一次只删一处

来源：RRSI 的 `b_min = 1`。
理由：删三处同时做，掉分了不知道是哪处。
代价：轮次变多。**接受这个代价**——归因能力比速度重要。

### 纪律 2｜删完真跑，取最差不取平均

来源：SHarP 的 3 次 + 配对 t 检验；Cortex 的门 2 `D ≤ τ`。
理由：平均值会掩盖"某一题彻底崩了"。
代价：评测量 ×k。**这 k 次不能省**——省了就等于回到"判断替代测量"。

### 纪律 3｜白名单在 AST 层硬编码，不在提示里叮嘱

来源：REFINE 的 42.9%。
理由：提示是软约束，模型会违反，而且违反时不会告诉你。
代价：实现成本。但这是**唯一被实证有效**的做法（57.1% vs 100%）。

## 一个必须先解决的度量问题

**现状**：`measure_k()` 给了四个口径，**主口径是 `K_lines_nb`（非空、非注释、非 docstring 行）**，理由是"字符数会被删注释刷分"。

**这个理由对，但换了另一种攻击面**：

| 攻击 | 对 `K_lines_nb` 的效果 | 信息真的少了吗 |
|---|---|---|
| 删注释 | 不变（本来就不算） | 没少，但可读性降了 |
| 改短命名 | 不变 | 没少 |
| **压成一行**（`a=1;b=2;c=3`） | **暴跌** | **一点没少** |
| **把函数内联展开** | 行数可能降 | 可能没少 |

**同理**，`metrics_pool.py` 的 `gzip_ratio` 是**比例**，和 SlopCodeBench 的 verbosity 撞同一个坑：**它分不清"100 行干净代码"和"10000 行干净代码"**。

**建议**：
1. **主口径保留 `K_lines_nb`**，但**同时强制报 `K_chars`**，两者**任一上升即不算改进**（互锁，防单向攻击）
2. 增加 **`K_ast_nodes`**（AST 节点数，对压成一行免疫）作为第三把锁
3. `gzip_ratio` 只作诊断，**不进判定**——它的语义是"冗余密度"，不是"描述长度"
4. 三者都按"**先 normalize 再算**"：去注释、统一格式、标识符不在度量范围内

# 第七部分　n 到底要多大（这条要先算再做）

经验 2 说了必须测 δ。但**δ 有多大，取决于 n 有多大**。

**最坏情形估计**（每任务二值、通过率≈0.5）：

```
单臂 95% CI 半宽 ≈ 0.98 / √N        （N = 任务数 × 重复次数）
```

| N | CI 半宽 | 能判的最小差异 |
|---|---|---|
| **3**（现状最小） | **57pp** | 判不了任何东西 |
| **13**（现状最大） | **27pp** | 只能判"崩了"或"翻倍了" |
| 50 | 14pp | 和 Growing Harness 实测的 ±11–13pp 对得上 ✓ |
| 200 | 6.9pp | 能判 7pp |
| **1000** | **3.1pp** | 能判 3pp |
| 2000 | 2.2pp | 能判 2pp |

**RRSI 用的就是几百到上万**：TB2 178 次试验、Harvey LAB 14,100 条判据、EngDesign 244。

**结论**：
- 我们现在 n=3~13，**任何小于 25pp 的结论都不可判**——包括"降了 44.6%"这类说法
- 要判 3pp 量级的改进，**需要 ~1000 个观测**（100 题 × 10 次，或 250 题 × 4 次）
- 配对比较能改善（同题两臂相关），但改善幅度取决于相关系数，**不能假设**

**这不是"要不要做"的问题**，是"不做则所有实验结论都不成立"。
