# 06 被测 agent 清单

> **一句话**：三类共 **5 个必选 + 3 个备选**。编码类必须留一个**强基线**兜底，
> 否则"提升"会被说成专挑弱 agent。

**选型标准**：论文里用得多（≥2 次）× 可改进空间大 × 能换 DeepSeek × 开源可跑。

---

## 一、总表

| 类别 | agent | 谁用过 | 可改进空间 | 用不用 |
|---|---|---|---|---|
| **编码/终端** | **Terminus-2** | RRSI、ModularRSI | 中 | ✅ **必选**（对标锚点） |

| | **OpenHands** | Meta-Harness | 中（已很强） | ✅ **必选**（强基线兜底） |

| | Codex | RHO | 小 | ⭕ 备选 |

## 二、为什么这么配

### 一个强 + 一个弱，缺一不可

HarnessX 的 **+44.0% 全部来自最弱的 Qwen3.5-9B**，强底座只有 +11.2%。

| 只留弱的 | 只留强的 |
|---|---|
| 分数好看，但被质疑「专挑软柿子」 | 严谨，但可能一点空间都没有 |

**所以编码类必须有 OpenHands 这种强基线。**

### "可改进空间大"不是感觉，有四条实证

| 证据 | 出处的意思 |
|---|---|
| 108 个组件只有 72 个被执行过 | 现成 agent 里**本来就有死组件** |
| 演化改动只有 53.1% 在 held-out 上方向一致 | 改完不验证 = 一半白改 |
| 增益来自 tools/middleware/memory，**不是** system prompt | 空间在**组件层**，不在提示词 |
| AIME/GPQA 上加脚手架几乎无增益 | "加东西"不一定有用，**该往删走** |

## 三、每个 agent 的定位

| agent | 它在实验里扮演什么 |
|---|---|
| **Terminus-2** | 与 ModularRSI 对齐的**唯一锚点**，主结果必须跑 |
| **mini-swe-agent** | **弱基线**：证明方法在"几乎裸的循环"上也能起作用 |
| **OpenHands** | **强基线**：证明方法不是只能对付弱 agent |
| **ReAct + toolbelt** | 知识工作的**主形态**（照 RRSI 的形状） |
| **分类 harness** | **最便宜的删测场地**（分钟级评测） |
| **检索 harness** | 组件边界最清晰，适合做逐段删测 |

---

## 四、落地三条

1. **一个 agent = 一个薄文件**：暴露「可编辑组件清单 / reset / step / 观察规范化」。
2. **底座是适配层的参数**，不是 agent 内的硬编码——换 DeepSeek 只改一处配置。
3. **每个 agent 先跑出 H0 基线**，跑不出就不许进主表（否则表里会有空格）。

## 五、待确认
