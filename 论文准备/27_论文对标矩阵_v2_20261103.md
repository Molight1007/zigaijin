## 〇、三条读表纪律

1. **证据级照旧**：A=一手核过 arXiv 页；B=读到正文；C=二手，**引用前必须核**。

3. **数字不可直接横比**：底座、基线、数据集都不同。本表只用数字判断「这个机制有没有被验证过」，

## 二、把矩阵压成一句话

**所有对手都在优化「分数 S」和「执行成本 C」；只有 Cortex 和 Perses 两条线把「验证」做成了
逐步的、可回放的纪律。我们的差异化不在再提一个指标，而在把这两条纪律搬进同一个回路：**

```
触达普查（Cortex） → 分层（L1/L2/L3/L4） → 消融/删除（SHarP + Perses）
   → 非单调 token 门（SHarP 的反例） → K 互锁（HarnessDev 的 LOC 教训）
   → 快照回退 + 账本（本工具已有）
```

## 四、按优先级该补什么

### P0：不补就对不起已经写好的分层

**P0-1 L3 消融执行器**（借 SHarP + Cortex，**2026-11-03 已完成**：`src/usecases/ablate.py`）
- 新增 `src/usecases/ablate.py`：一次关一个模块/函数，跑 S、token、K，再恢复。
- **不是删除**：消融只关开关，代码还在；这样能测「零贡献」而不破坏调用契约。
- 判据：`S_after ≥ S_before − δ` 且 `token_after ≤ token_before` 才记「零贡献」；
  否则记「有贡献」，并写入账本。
- 验收：拿一个已知无贡献的模块（如未接线的 helper）应判零贡献；
  拿一个真实控制模块（如 gate 分支）应判有贡献。

**P0-2 trace → 触达数据适配器**（借 Cortex + HarnessDev，**2026-11-03 已完成**：
`src/adapters/touches_from_trace.py` + `cli exposure`）
- 支持 coverage.py JSON、`{"executed": {path: [line]}}`、纯 mapping 三种输入。
- CLI `exposure` 输出 `output/touches.json`，可直接给 `simplify --touch-json`。
- **明确不接** OpenHands ActionEvent 的文件级轨迹：文件级 ≠ 行级触达，硬接会制造假 L2/L3。
- 验收：coverage JSON → touches.json → `plan` 的 L2/L3 分层 roundtrip 已有测试覆盖。

**P0-3 简化轮入账**（借 RRSI 的历史条件化，**2026-11-03 已完成**）
- `record_deletion`（`simplify.py`）把试删三态 `kept / rolled_back / blocked` 分开入账；
  `record_ablation`（`ablate.py`）记录四类消融结论。
- 缺 score 时标 `extra["evaluated"]=False`，**不拿 0 冒充实测**；K 用 complexity 池的
  `K_sloc`（删除路径没有 `K_lines_nb`）。
- CLI `simplify --ablate/--apply --ledger <jsonl>` 追加记录，同一轮共享 `round_id`。
- 消费端：`history_index` 把账本变成 `unit_key → 最近结论`，`plan` 标注
  `tried / retry_ok`；`rolled_back / blocked / kept / contributes-positive`
  默认不再自动提，`--retry-tried` 可重试。
- 验收：同一候选第二次出现在 dry-run 里会带 `[已试过:…]`，且不进入执行池。

### P1：把「测过」升级成「可归因」

**P1-1 评测前规则预过滤**（借 RRSI critic，**2026-11-03 已完成**）
- 规则不再写死旧题库：`patterns_from_tasks()` 从当前题集派生 **题号** 与
  **判据期望值**；`3` / `yes` / `beta` 这类短值不收，避免正常卡被误伤。
- 三层落点，全部在评测之前：
  1. **基线预筛**：`evolve_round` 先筛基线文本，泄漏就直接返回，不花 `stage1`；
  2. **卡级守卫**：`run_card(guard=...)` 在提案落盘与两轮 LLM 审核**之前**拦截，
     命中即把原因回灌给改造员重提，3 轮不过记 `blocked`；
  3. **整段候选兜底**：多张卡拼起来才出现的泄漏，在 `_verify` 前再筛一次。
- 被拦的候选 `verified=None`（没测，不是 0 分），轮次证据写入 `round.json` 的
  `critic` 字段；`--no-critic` 只用于对照实验。
- 验收：引题号/抄答案的卡必被拦；正常改写不误伤；泄漏候选不触发 `_verify`。
  （`src/tests/test_critic_tasks.py`、`src/tests/test_pipeline.py`）

**P1-2 feedback / held-out 方向一致率**（借 HarnessDev，**2026-11-03 已完成**）
- 新模块 `src/domain/generalization.py`：`direction_consistency()` 给单轮判定，
  `summarize_directions()` 给多轮比例（分母只算**两侧都测到**的轮次）。
- 口径：`ΔS` 都用通过率差（不是 pp）；`|ΔS| ≤ delta` 记为「平」，
  两侧都平算同向但 `informative=False`；缺一侧 → `computed=False`，
  **不把缺数算成不一致**。
- `evolve_round` 新增 `heldout_tasks`：只用于诊断，不进 `gate()`；
  先测 held-out 基线、再测候选，结果落 `heldout` 与 `direction_consistency`。
  没给 held-out 题集时字段仍在，标 `computed=False` 并写明原因。
- CLI `evolve --heldout-task-file`；held-out 题**不参与** planner/rewriter，
  也不进泄漏规则（否则守卫会把 held-out 题号回灌给改造员）。
- 验收：同向 → `consistent=True`；反馈涨/held-out 跌 → `False`；
  缺数 → `computed=False`。`src/tests/test_direction_consistency.py`

**P1-3 per-task token 采集接进评测**（**2026-11-03 已完成**）
- `RunResult.tokens: int | None`：None = 未采集，**不拿 0 冒充**；OpenHands 从轨迹读，
  读不到就保持 None。
- `Trial.tokens_known`：历史 `tokens=0` 默认值明确标成「未采集」；`adapt` 保留真值。
- `Score.tokens_total / tokens_per_task`：**整批 trial 都有值才填**，任何缺口（缺 token、
  有 missing、题数不齐）一律 None——部分和会让 token 门误判「变省了」。
- `Score.token_payload()` 直接喂 `token_gate`；已有单测证明聚合值能触发拒绝。
- **内置一键 A/B 已接**：`simplify --ab-task-file … --ab-skill-file …` →
  `eval-skill` 子进程（删完的代码重新加载）→ 最后一行 JSON 直接喂 `token_gate`；
  外部 `--token-cmd` / `--measure-cmd` 保留，用于接别人的评测器。
  `src/usecases/simplify_ab.py`、`src/tests/test_simplify_ab.py`
- 边界：内置 A/B 仍跑真实 sandbox，**要模型与 API key**；它省掉的是
  「在项目外再拼一份聚合口径」，不是评测开销。

### P2：算子与搜索（等 P0/P1 稳定后再做）

**P2-1 L4 改写算子**（借 CodeTaste + REFINE，**2026-11-03 已完成**：
`src/domain/code_rewrite.py` + `src/usecases/rewrite.py` + `cli simplify --rewrite`）
- 两个低风险算子已落地：`duplicate-branch` 合并同体分支、`empty-wrapper` 内联空壳函数。
- **差分测试分两半**：静态半边是算子自带的 AST 等价自检（不通过就返回 `ok=False`，
  不写盘）；运行时半边是 pytest / 可注入 verifier。两层都过才保留，任一不过即快照回退。
- 拒绝边界写死在算子里，不靠调用方自觉：`duplicate-branch` 拒 no-else / 体不同 / 条件含
  Call/Await/Yield/walrus / 单行内联体 / 多行字符串；`empty-wrapper` 只收模块级无装饰器、
  纯位置参、单 `return g(...)` 的函数，且要求被调方在模块级可解析、所有引用都是同模块内的
  直接调用（跨模块 import、别名、属性引用、`__all__`/字符串引用一律拒）。
- 不做「让 LLM 自由重构」——REFINE 已经证明等价性保证不了。
- 验收：`src/tests/test_code_rewrite.py`（21 项，含各类拒绝用例）、
  `src/tests/test_rewrite_rollback.py`（12 项，闭环 + CLI 端到端）、全套 1020 项通过。
- 真实仓库边界：本仓库只有 2 个 wrapper 可内联（`_archive_skill_only`、`_snap`），
  其余 7 个因方法/默认参/属性被调方被拒，59 条候选属未支持的改写类型——
  **不声称「L4 已能处理所有结构改写」**。

**P2-2 候选池 + 历史条件化生成**（借 RRSI + Meta-Harness + RHO，**2026-11-03 已完成**：
`src/domain/candidate_pool.py` + `orchestrator.evolve_round`）
- 已把「N 张卡依次改同一份副本 → 一个候选」改成「每张卡改**各自的原样副本**
  → N 个候选」。这顺带修掉一个静默错位：后续卡的行号来自原始档案，在已改过的
  文本上应用，`before` 若仍能找到就是改错了位置。
- 去重口径是**文本指纹**（换行/行尾空白归一），不是环节名——同一环节的两张卡
  产出不同文本时，那是两个真正的备选方案。候选与基线相同也直接丢弃。
- 排序用账本两项，不引入向量库：`unit_fresh`（环节是否在账本里出现过）+
  `idea_novelty`（与**被拒**假设的字符三元组 Jaccard 距离）。接受过的记录不参与
  字面惩罚；缺改动说明时 `idea_novelty=None`，只按环节新鲜度排。
- **排序不参与判定**：选中的候选照旧过 gate；新颖性只决定先测谁。其余候选的
  文本落在 `out/candidates/card-XX/work/`，摘要进 round.json，不重复生成。
- 账本三态：选中的候选记 `selected`；没选中的候选**不进账本**（没测过 ≠ 被拒过，
  否则下一轮会白白避开一个还没试的方案）；失败的卡照旧记 `gave_up`/`blocked`。
- 验收：`src/tests/test_candidate_pool.py`（12 项）、
  `src/tests/test_candidate_pool_round.py`（9 项，含独立副本、去重、历史排序、
  账本三态），全套 1041 项通过。
- 边界：本轮仍只验证排名第一的候选；「N 个候选都测」需要评测预算，当前不做。

**P2-3 模块级演化**（借 ModularRSI，**2026-11-03 已完成**：
`src/usecases/module_ab.py` + `orchestrator.evolve_round(module_ab=True)` +
CLI `evolve --module-ab`）
- 逐模块独立评测：`pass_rate >= baseline - δ` 才算通过非劣筛查。缺基线直接关闭
  （不知道和谁比就不烧预算）；评测异常或缺 `pass_rate` 一律不算通过。
- 合并按行号**从下往上**：上面的改动会移动下面所有行号，从下往上改，
  已落盘的位置不会被后续改动扰动。合并走 `apply_proposal(card=...)`，
  与单卡落盘共用同一套边界校验。
- **合并体必须复测**：两个各自不掉的改动可能互相抵消。复测不低于最佳单模块 - δ
  才保留；否则退回最佳单模块；只有 1 个模块通过时不做合并复测。
- 合并失败/退化都留痕（`merge_errors`、`reason`）；`change_summary` 只报真正
  进入选中项的模块，不把通过筛查但没合并的模块算成已落地。
- 账本：合并选中时只记一条 `module_merge/selected`，不再逐卡记 selected；
  失败卡照旧记录。`module_ab` 隐含 `verify=True`——模块结论也要过 gate。
- 验收：`src/tests/test_module_ab.py`（9 项：非劣、退化、合并复测、合并失败、
  评测异常、JSON 形状）、`src/tests/test_module_ab_round.py`（4 项：接线、
  单模块、全退化、默认关闭），全套 1054 项通过。
- 边界：模块仍由任务卡给定，不是自动枚举；合并只处理同一文件的 edits；
  N 个模块 = N 次评测，是用预算换归因。

**P2-4 DPP 核心集选题**（借 RHO，**2026-11-03 已完成离线复现**：
`src/domain/coreset.py` + `src/usecases/coreset_eval.py` + CLI `coreset`）
- 质量 = 失败率的平滑版本，多样性 = 指令文本字符三元组余弦；DPP 贪心 MAP，
  O(k·n²)。30–200 题不需要向量库，也不引新依赖。
- 题面重复会让行列式边际归零，此时按难度补足到 k——预算是固定的，
  不能让一批同质题把 k 缩水。缺失 trial 不计入通过率；一题全缺失直接退出选题。
- 离线对照：一份 round.json（evolve 的 `trials` vs `verified.trials`，
  或 M0 的 `full` vs `short`）先算全量 ΔS，再算 DPP / 最难 / 随机（多种子）
  子集的 ΔS、绝对误差与方向一致率。命令：
  `python -m src.cli coreset --round out/round.json --tasks tasks/v1.jsonl --k 10`。
- 合成轨迹冒烟：4 题两组（2 道同质难题 + 2 道同质易题），全量 ΔS=10pp；
  DPP 选「1 难 + 1 易」→ 10pp（误差 0），最难选「2 难」→ 20pp（误差 10pp）。
  这说明多样性不是装饰：只选最难的会放大效应量。
- 验收：`src/tests/test_coreset.py`（13 项：多样性、补足、缺失、种子、宏平均）、
  `src/tests/test_coreset_eval.py`（6 项：两种 round 形状、误差、缺失、指令加载），
  全套 1073 项通过。
- **边界**：还没接进 `evolve` 的快速轮；离线数字用同一批轨迹选题又定答案，
  是乐观估计。下一步需要一份真实多任务 round 再决定是否启用。

## 五、明确不借的

| 不借 | 原因 |
|---|---|
| **token 级 prompt 压缩当核心**（LLMLingua/ACON） | 压的对象是喂给模型的 token，不是 harness 源码；换指标会被一眼看穿 |
| **「越短越好」**（ACE 反例） | 一次摘要把 66.7% 压到 57.1%，比不压还差；长度只能是**同 S 下的接受准则** |
| **开放式无限增长**（DGM） | 没有 K 压力就会膨胀；HarnessDev 的 17,111 行净增就是证据 |
| **压成向量**（Gist/AutoCompressor/ICAE） | 人审计不了，与「可复现、可归因」直接冲突 |
| **全自动重构不验证**（REFINE 的教训） | 静态检查只是风险证据；我们的门必须是行为等价 + 回退 |
| **只报最好一轮**（多篇的通病） | 我们已有账本与 paired CI，没有理由退回去 |

## 六、补完之后，我们剩下的位置

矩阵补完不会让「K 作为接受准则」这个位子消失，但会让它从**主张**变成**可运行的系统**：

1. **K 独立否决**：L1–L4 分层 + K 互锁 + token 门，三条同时成立才留。
2. **统计 oracle 下的程序精简**：Perses 的 oracle 是二值 crash；我们的 oracle 是带噪声的通过率，
   所以 δ、k 次试验、缺失率必须进同一套门——这是软件工程侧没有的一层。
3. **可诊断性收益**：HarnessMinimizer 的 28%→44–51% 是唯一现成的实证支点；
   如果我们在自己的任务上复现「精简后归因更准」，这比「省 token」更难被反驳。
