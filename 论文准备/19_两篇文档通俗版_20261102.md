# 第一部分　RRSI 与自压缩

## 1.1 先说问题是什么

大模型权重冻结不动，改的是它外面那层壳——提示词、控制流、工具、记忆、子智能体（统称 **harness**）。

改法很朴素：让模型读自己的失败，提一版新壳，跑一遍，好就留下。

**问题是这套朴素做法会崩**。三个崩法（RRSI 论文自己归纳的）：

1. **只对考卷有用**：学到了"这道题这么答能过"，而不是"这类题该怎么想"。
2. **追噪声**：分数涨了，其实是评测抖动，换个场景就打回原形。
3. **越改越胖**：只会加规则、加分支、加提示，从不删。因为删了短期容易掉分。

第 3 条是自压缩要治的病，前两条是 RRSI 要治的病。

## 1.2 RRSI：七个旋钮

RRSI 的做法不是"改得更聪明"，而是**限制它怎么改**。原文叫"正则化"，说白了是七个旋钮。

**提议侧 —— 管"这一轮许你动多少"**

| 旋钮 | 大白话 | 默认 |
|---|---|---|
| 退火编辑预算 `b_t` | 一轮最多打包几处独立改动。开头宽松（4），后面收紧（1），这样"是哪一处带来的提升"才好归因 | 4 → 1 |
| 编辑历史 `L_t` | 每次改动的假设、diff、分数变化全记账。被证伪的假设别再提第二遍 | — |
| 结构化探索 `E_t` | 连续 3 轮（`w=3`）涨幅落在噪声里 → 判定停滞，强制留 1 个名额（`m_draft=1`）去碰**从没碰过**的组件 | w=3, m=1 |
| 剪枝目标 `B_t` | 某组件连续 4 轮（`n_prune=4`）没带来正收益 → 挂上"待删"标签交给提议端 | 4 |

**选择侧 —— 管"什么样的改进够格留下"**

| 闸门 | 大白话 | 默认 |
|---|---|---|
| 噪声下限 `S ≥ S* − δ` | 不许比**历史最好**低出一个噪声带。注意是 `S*`（至今最佳），不是上一轮 | δ 分域实测 |
| 成本规则 `ΔC ≤ β₀ + β₁·ΔS` | 涨分才能涨成本。涨 1 分允许多花多少 token，由 β₁ 定 | β₀≈0.10, β₁≈24~45 |
| 带内整形 | 涨幅太小（`ΔS ≤ δ`）时不算赢，改用线性打分 + 给"碰了新结构组件"（ν）一点加分 | 权重论文未公开 |

**外加一道前置门：critic 泄漏预筛。**

这一步最容易讲漏，但它是整篇的命门——**审查发生在评测之前**。候选 diff 先被读一遍，命中"写死任务名 / 写死答案 / 名为机制实为空操作 / 想偷看评分器 / 藏了没申报的改动 / 无退出路径的循环"任一条，直接拒，**根本不给它跑分的机会**。

为什么顺序不能反？因为一旦让它跑，它会拿到一个虚高的 evolve 分数，这个分数就进入了历史，后面所有"跟历史最好比"的判断都被污染。

## 1.3 一轮长什么样

原文 11 步，合并成 6 步：

1. 在演化集上跑一遍，看失败在哪
2. 算这轮的编辑预算 `b_t`，组装探索指令（是不是停滞了？）
3. 算剪枝目标（哪些组件该挂了）
4. 提议一批候选，每处改动打上"组件 + 假设"标签
5. **critic 先审** → 通过的才去跑分
6. 三条闸门逐项过 → 全过的进可采纳集 → 取分最高的替换存档

第 6 步的关键词是**非补偿**：三项是"与"关系，不能用高分补成本超支。原文反复强调这点，因为一旦允许补偿，最省事的作弊路径就是"堆算力刷分"。

## 1.4 自压缩：把"变短"当目标，而不是当副产品

RRSI 的成本门只是**拒绝不划算的增长**——它不主动求你变短，只要你别太胖就行。

自压缩更进一步：**源码长度本身就是优化目标**。

度量很土：`K(h) = gzip(harness 全文).字节数`。土，但可算、可复现、跨版本可比。

三个压缩动作：
- **删**：重复表述的同一规则、没作用的检查、只为凑字数的措辞
- **并**：散在多处的同义规则归并成一条，别处引用（⚠ 见 1.8 第 4 条，文本 harness 里这条不好落地）
- **换**：用更短的等价表示替掉长表述

接受准则分两种情形：
- 变复杂了（`ΔK > 0`）→ 要求行为收益**按比例**偿付
- 变短了或没变（`ΔK ≤ 0`）→ 行为不掉就放行

还有一条：非反馈轮（没有外部分数可看的那几轮）额外做一次**纯压**——挑一处冗余删掉，分不掉就采纳。理由是"外部反馈是稀疏资源，不能干等"。

## 1.5 C 和 K 不是一回事（全文最容易搞混的一处）

原文专门澄清了，值得单独拎出来：

| | 度量什么 | 举例 |
|---|---|---|
| 成本 `Ĉ` | **跑一次要花多少**（运行时 policy token） | 同一份提示，短，但每轮让它做大量反思 → C 高 |
| 描述长度 `K` | **壳本身有多难描述、多冗余**（gzip 字节） | 提示很长，但每轮只是照念 → K 高 C 不高 |

**量纲不同，不可互换，也不该相加。** 这句话要记住，因为评审最爱问"你这不是把成本换了层皮吗"。

## 1.6 叠加：先审，后瘦

两套不是竞争，是**串联**：

```
候选 ──► RRSI 四道闸门（守能力）──► 自压缩复杂度门（守简洁）──► 留 / 弃
```

分工：
- RRSI 拦：泄漏的、噪声赢家、不划算的增长、没用的机制
- 自压缩 削：通过准入之后还残留的冗余

为什么不冲突？因为它们作用在**不同的量**上——一个问"能力是不是真的涨了"，一个问"描述是不是真的短了"。

## 1.7 三者对照（简化成 5 行）

| 维度 | RRSI | 自压缩 | 叠加 |
|---|---|---|---|
| 优化目标 | 正则约束下最大化分数 | 分数不降 + 长度最小 | 两者同时 |
| 复杂度角色 | **准入门槛**（拒绝不划算的增长） | **平级目标**（主动求简） | 门槛 + 目标 |
| 靠什么删 | 收益窗口 + 删除标签（启发式） | 压缩算子（求等价更短） | 两者叠 |
| 没反馈时 | 转不动 | 能转（ΔK 自己就能算） | 每轮评估 + 非反馈轮纯压 |
| 抗泄漏 | critic 逐 diff 审 | **几乎没有**（见下） | 靠 RRSI 那一侧 |

最后一行是全篇最该记住的：**ΔK 是字节数，它测得到任何内容，但不区分内容来源。** 一个把演化集任务名写死的候选，只要顺手删掉两段重复措辞，ΔK 照样是负的。

## 1.8 读的时候要留意的 6 个坑

> 依据：`资料文档/05_调研与证据/RRSI与自压缩说明_审核意见_20261029.md`（逐节核对过原文表 5）

**① 三处超参不是"论文默认值"**

| 文档写的 | 论文实际 |
|---|---|
| `δ = z·sd(ΔS)`，z=2 | 论文是**分域实测**：TB2 3/178=0.017；Harvey LAB 60/14,100=0.004；EngDesign 5/244=0.020。全文无 z=2 |
| β₁ = 40 | 三域 44.5 / 35.4 / 24.4，无一处是 40 |
| w_s=100, w_c=15, w_n=0.5 | 表 5 未列这三个；正文明确写"编码实例设 **w_s=0**" |
| `repair_rounds=5` | 论文**没有返修机制**，critic 直接拒 |

对外引用前必须改，否则一问就穿。**建议做法**：不给"默认值"，改列"分域实测值"——更硬，也更难挑。

**② "ΔK 无损 ⇒ 行为不变"是偷换。**
gzip 的无损指"字节可完全还原"，跟"harness 行为不变"毫无关系。表 2 / 表 3 那两格"抗泄漏"写法要改，否则等于自证。

**③ 压缩分支的门槛必须锚 `S* − δ`，不是"比上一轮不显著下降"。**
原文 §3.3/§3.4/§3.5 四处强度混用（"不变"/"不下降"/"不显著下降"）。若真按最后一档放行，每轮可掉 δ 以内，T 轮累积掉 T·δ——这正是 RRSI 用 `S*−δ` 要防的"小步下坡"。压缩分支只跟上一轮比，就成了一条新的棘轮式退化通道。

**④ §3.2 的"其余处改为引用"在纯文本 harness 里不可执行。**
提示词没有 include 机制，"改为引用"要么靠模型自行联想（等价性无保证），要么得 harness 本身支持展开。应限定在配置、工具描述、控制流这类可程序化展开的构件上。

**⑤ 新颖度加分（ν，鼓励新增）和剪枝（鼓励删除）方向相反，叠加层没处理。**
同一组件可能这轮靠 ν 拿准入、下轮被纯压删掉 → 振荡。两种补法：① 冷却期（因 ν 准入的组件 `n_prune` 轮内不得成为删除目标）；② 合并记账（ν 加分与 K 减分记在同一账户看净值）。**这是"叠加"真正的方法论缺口，比排版问题重要得多。**

**⑥ §6 说"不涉及任何具体评测配置与结果"，但 §2.2–2.4 通篇给超参默认值。** 自相矛盾，删一句就行。

# 第二部分　Harness 可压缩性分析报告

## 2.1 它想证明什么

三段话：

1. **两个通过率一样的 harness，更短的那个理解更深、泛化更好。** 冗长的规则堆叠不是"能力强"，是"刷题刷出来的过拟合"的结构性标志。
2. **现在的自改进系统全都在优化两个量：分数 S 和成本 C。没有一个把"源码长度 K"当回事。** 所以它们必然越改越胖。
3. **应该把 K 变成第三个维度**，写进接受准则，构成三目标帕累托前沿。这是防"AI 写的屎山"的护栏。

## 2.2 理论链条，用人话讲

四步，都是别人半个世纪前就做好的：

| 年代 | 谁 | 说了什么 | 大白话 |
|---|---|---|---|
| 1964 | Solomonoff | 归纳推理的形式化 | **能最简短描述数据的程序，就是最好的预测器** |
| 1965 | Kolmogorov / Chaitin | 复杂度 K(x) | 一个东西的"复杂"= 能生成它的最短程序有多长。**压不动的，才是真随机** |
| 1978 | Rissanen | 最小描述长度 MDL | 把"最短程序"变成可算的两段码长：`L(模型) + L(数据\|模型)`。两项之和最小 = 理解最深 |
| 2005+ | Hutter / Rae | 最优压缩 = 最优智能 | 大模型的交叉熵损失本质就是压缩码长；损失越低 = 对世界结构建模越深 |

**一个绕不过的坎**：`K(x)` 不可计算（停机问题）。所以工程上只能不断逼近上界——找不到"最短"，只能一直找"更短"。这句话很重要，它把"精确最优"的包袱卸掉了，也是"gzip 字节数"这种土办法能上桌的理由。

## 2.3 证据：系统确实在变胖

报告从三个角度举证。**注意：这几条数字的来源强弱不一样，见 2.9。**

| 症状 | 证据 |
|---|---|
| **提示爆炸** | HarnessPro 记录：Agent 在无关配置文件上反复倾倒日志，单次任务烧掉 **251 万**输入 token |
| **规则堆叠** | RRSI 归纳三类耦合：基准特定拟合 / 评估噪声追逐 / 复杂度累积。特征是**单调不减**（只会加）、**路径依赖**（加了就撤不掉）、**非结构化**（打补丁不是重构） |
| **边界补丁** | HarnessPro 演化出"五档推理强度路由"和"工具调用 14 次强制切经济档"——报告认为这恰恰证明内层策略还没被压到精炼：真懂了任务，不需要五档切换，也不需要 14 次熔断 |
| **反馈不可信** | 纯 LLM-as-judge 对失败案例的召回率只有 **41.7%**，加合成单测才到 83.3% |

报告的洞见在于：这些 runtime 钩子本身也是"需要被度量的 L(M)"。复杂度从"解题逻辑"转移到了"控制解题逻辑的逻辑"。

## 2.4 三把尺子，各有各的瞎区

| 尺子 | 例子 | 能量什么 | 测不到什么 |
|---|---|---|---|
| **静态结构** | 圈复杂度 CC、Halstead Volume、可维护性指数 MI | 分支堆叠、样板复制、代码体积 | 语义冗余（换语法糖就变）；也**不区分防御式分支和刷题式分支** |
| **信息论** | gzip 压缩比、Shannon 熵、LLMLingua 有效 token 比 | 字符级冗余、重复度 | 语义等价的改写；也不懂"短但错"的伪压缩 |
| **语义判定** | LLM-as-judge、抽象层度 LoA | "这段分支是不是为刷分硬加的" | 裁判本身召回率只有 41.7%；抽象层度只能近似估 |

结论：**必须多源交叉**。报告给的建议配方是——MI/CC 当硬闸门 → gzip/LLMLingua 当早期信号 → LLM 裁判 + 合成单测当最终判定 → 抽象层度当长期追踪量。

## 2.5 四级压缩算子（风险从低到高）

这是报告里最可执行的一节。**顺序不能乱，越往后越贵越危险。**

| 级 | 动作 | 为什么安全/不安全 |
|---|---|---|
| **1. 删** | 死代码、走不到的分支、孤儿函数、重复提示、零信息客套话 | 最安全。任意可达路径上不影响可观测输出 = 语义保真变换。LLMLingua 报告最高 ~20 倍压缩 |
| **2. 并** | 五个手写分支 → 一个连续预算函数；散落错误处理 → 公共装饰器；重复子指令 → 一条系统前提 | 中等。合并分支容易漏边界条件，抽象通用规则容易洗掉长尾判别细节。**必须配反事实单测** |
| **3. 蒸** | 多种机制干同一件事（提示引导 + 工具包装 + 运行时钩子 + 后验校验）→ 用一种更短的机制吸收，其余整体删 | 高风险。验证难度组合爆炸；学生可能只拟合了教师的高分路径，把防御护栏丢了 |
| **4. 搜** | 把"在验证集上行为等价"当目标函数，搜最短的 prompt+code 组合 | 最高风险。极易"验证集更短更好、长尾悄悄失效"；过度最小化还会毁掉可读性，锁死下一轮演化 |

报告自己的定位判断：**第 4 级是收益放大器，不是默认动作。** 只有前两级把系统收敛到合理形态了，才值得为最后一截长度付昂贵验证代价。

## 2.6 怎么接进演化回路（三个动作）

**动作一：三维帕累托。**
每个候选同时报 `S`（分数）、`C`（执行成本）、`K(h)`（静态复杂度）。被支配的定义变成：A 在 S 上不低、C 上不高、K 上不高，且至少一项严格更优 → B 淘汰。

这一步能拦住"分数高、成本可接受、但机制在变胖"的隐性退化——这正是 δ 噪声带和成本闸门共同的盲区。

**动作二：反事实剪枝轮。**
光有帕累托还不够，因为路径依赖：早期接受了一个"略优但偏复杂"的候选，后面所有变异都得在它基础上叠。

所以每隔若干轮强制插一轮**只许简化、不许加新机制**：从当前最佳出发，只跑简化算子，`S` 不降（或在 δ 内）且 `K` 显著降的必须接受，哪怕 `C` 略抖。作用相当于定期注入一次"沿 K 梯度下行"的压力，打断单向堆机制的正反馈。

**动作三：停止条件要重构。**
现在的停止信号是"分数收敛"或"连续 N 轮无候选通过"。这会错过一个重要阶段——**分数已经不涨了，但还能继续变瘦**。

新条件：S、C、K 三个滑动窗口的改进幅度**都**低于阈值才停。只要还有一个在显著改善，就继续。

**配套细节**（容易被忽略但决定成败）：
- `K` 必须**跨版本可比**：不能因为重命名变量或重新格式化就剧烈波动 → 优先选对语义等价变换不敏感的度量（AST 节点数、gzip 压缩率），裸 LOC 要先规范化
- 权重**别硬编码**：保留 lite / medium / heavy 三档偏好旋钮，但"机制不能无限膨胀"在所有档位都是不可妥协的底线
- `K` 惩罚宜**退火**：早期弱（allow 探索），S 收敛后加大（逼简化）。这与 RRSI 的退火预算同构，只是退火对象从算力预算换成了复杂度预算

## 2.7 三条不能碰的红线

**红线一：防御式冗余。**
输入校验、断言、空值防护、白名单、边界检查、异常不吞没——每一处都在拉高 CC / LOC / Halstead Volume，但它们是**故意的**。

为什么危险？因为演化压力指向"在 evolve 集上拿分"时，最容易通过的剪枝恰好是删掉那些"从未在训练 case 里触发"的防御分支。训练集里没有空指针，删掉 if-null 检查既省 token 又不会立刻掉分。

**做法**：计算 K 或 CC 时必须对防御式代码做**白名单豁免**，或把它识别为"结构化冗余"而非"噪声冗余"。否则最优压缩方向会系统性偏向脆弱实现。

**红线二：长尾遮蔽。**
平均指标天然偏向高频路径。某条捷径在 80% 的 case 上省 token、在 20% 的 case 上要更多防御——以平均码长为目标，会持续奖励前者、惩罚后者，直到长尾能力被剪没。

更糟的是评估偏差会放大它：LLM 裁判只看见不到一半的失败，压缩等于"在不到一半的失败被看见的情况下做减法"，被剪掉的恰好是评估器没能力发现、但在真实场景中触发的分支。

**红线三：伪压缩。**
把五个独立判断合并成一个表驱动分派，LOC 降了、Halstead 降了，但真正的算法信息量（规则数、边界条件数、失败模式数）一个没少，只是被**折叠进了数据结构**。

MDL 理论自己承认这个困境：`K(x)` 不可计算，任何实际编码（包括编程语言本身的语法）都只是近似，换个抽象范式就得到不同长度。

## 2.8 四阶段路线图

| 阶段 | 做什么 | 为什么从这里开始 |
|---|---|---|
| **1. 提示层压缩 + 冗余审计基线** | 旁路接一个审计模块，只测不改。对系统提示 / 工具 schema / few-shot / 运行时日志分别算 token 数、gzip 字节、LLMLingua 可删比例 | "先测量、不改动"。用最小风险回答"我们的 harness 到底有多冗余" |
| **2. 代码层行为保持型剪枝** | 开一条独立于主演化的"简化分支"，只跑死代码消除 / 提取嵌套为具名函数 / 提前返回 / 合并重复规则。过三重门才算等价 | 提示层摸清底了，再动代码。**必须列"禁止触碰清单"**（assert/raise、白名单分支、错误处理路径，AST 层保护） |
| **3. 机制层蒸馏** | 反复出现的跨任务模式 → 蒸成更短的元机制。用 MDL 两部分编码判断：抽象省下的代码量，够不够抵新增参数描述长度 | 前两级已识别出"哪些模式值得抽象" |
| **4. 复杂度正则进接受准则** | `K(h)` 正式作为第三目标，接受准则升级为三维非支配 | 从"外挂压缩"跃迁到"内生正则" |

阶段 1 的具体实验设计（报告写得挺实）：
- **影子压缩**：evolve 集和留出 OOD 集各保留"原始提示"和"压缩提示"两条通道，**只有原始通道参与接受决策**，压缩通道只做离线对照
- 压缩强度取 100% / 75% / 50% / 25% 四档
- 产出三样：冗余热力图（按模块标可压缩率）、压缩比—得分下降帕累托曲线、失败案例清单（分"冗余成功删除"/"必要信息误删"/"压缩后反而涨分"三类）
