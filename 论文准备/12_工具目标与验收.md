# 12 工具目标与验收

> **一句话**：一条命令，把「换 agent / 换基准 / 换底座 / 开关一个机制」跑成一份能进论文的记录；
> 四张表由工具生成，不由人手抄。

**唯一判断标准**：论文里每个数字，都能追溯到一条命令。

---

## 一、目标长什么样

```bash
python -m exp run \
  --agent terminus2 --bench tb2:2.0 --backbone deepseek \
  --seeds 3 --k 3 --gate k_veto --guard on --pool evolve

python -m exp report runs/xxx --out tables/
```

跑完 `tables/` 里应直接出现四张表，列名与论文模板一致。

---

## 二、六个能力（每个都有"失败定义"）

| 编号 | 能力 | 什么算做完 | 什么算失败 |
|---|---|---|---|
| **G1** | 适配层 | 新增 agent **只改一个新文件** | 换 agent 要动主流程 |
| **G2** | 组件级 K | 连算两次结果一致，能出分解表 | 只能给总数 |
| **G3** | 两条删除路线 | 删测表每行带前后 S；**"不可判"是独立取值** | 删测靠人记 |
| **G4** | 判定器 | S+0.5/K+30% **必拒**；S 不变/K−20% **必受** | K 只进加权分 |
| **G5** | 双池 | 演化进程读量外池**抛错** | 只靠约定 |
| **G6** | 报告 | 四张表自动生成，带 CI 与 run_id | 要人工算 |

---

## 三、明确不做

| 不做 | 原因 |
|---|---|
| 自研 agent 框架 | 用现成的，我们只做外层 |
| 训练 / 微调 | 全课题前提是冻结权重 |
| 造数据集 | 只用公开基准 |
| 图形界面 | 唯一消费者是论文 |
| 分布式调度 | 单机串行即可（**测试本身要求串行**） |
| "提示词优化器" | 我们是**删**，不是改得更好 |

---

## 四、现状差距

| 能力 | 现状 | 差距 |
|---|---|---|
| G1 适配层 | 单场景 | **需新建** |
| G2 组件级 K | 只有 skill 行数 | **需重建** |
| G3 删除 | 只覆盖 5 段文本 | **需扩展** |
| G4 判定 | 有帕累托，仍留买通余地 | **需收紧** |
| G5 双池 | 有样本池，无隔离 | **需新建** |
| G6 报告 | 有埋点，无报表 | **需新建** |

---

## 五、三级验收

| 级别 | 内容 |
|---|---|
| **MVP** | TB2 **单题**跑通 H0 vs H0+K，3 次极差 ≤ δ |
| **可投稿** | G1–G4 达标，能出主结果表与删测表 |
| **完整** | G1–G6 全达标，四张表自动生成 |

---

## 六、论文产物现在能不能出

| 产物 | 依赖 | 现在 |
|---|---|---|
| 主结果表 | G2+G4+G6 | ❌ |
| **删测证据表** | **G3** | ❌ |
| 消融表 | G3+G4 | ❌ |
| 双池 gap 图 | G5 | ❌ |
| 可复现性附录 | G1+G6 | ❌ |

**五个产物一个都出不来——这就是目标存在的意义。**

---

## 七、四条硬失败

1. 换一个 agent 要改主流程 → 没有适配层
2. K 给不出分解 → 组件级删测无从下手
3. 删测结论靠人判断 → 回到启发式，核心创新归零
4. 论文数字要人工从日志抄 → 审稿第一问就挂

---

## 八、下一步只做一件事

**G1 两个 agent + 一条命令 + 一条记录 + 三次重跑极差 ≤ δ。**

这一条跑通之前，讨论 K 的口径都是空的。
