## 二、算法不是最好：找到 2 个真缺陷

### 缺陷 A｜`R1`（纯示例段）**在实践中永不触发**

`classify()` 的检查顺序是：标题 → 强制词 → **契约** → 代码块 → … → **示例**。

而 `CONTRACT_WORDS` 里包含 `print` / `output` / `report` / `echo` / `return` ——
这些恰恰是示例里最常见的词。**示例几乎总含契约词，于是永远走不到 R1。**

实测 9 种输入：

| 输入 | 修前 | 修后 |
|---|---|---|
| `For example, three lines gives ROWS=3.` | R1 删 | R1 删 |
| `Example 1: df = read_csv('a.csv'); print(df.shape)` | **契约·留** ✗ | **R1 删** ✓ |
| `Example: output looks like ROWS=3` | **契约·留** ✗ | **R1 删** ✓ |
| `For example, the agent will report 3 rows.` | **契约·留** ✗ | **R1 删** ✓ |
| `Note: we used print before...` | **契约·留** ✗ | **R2 删** ✓ |
| `Example: output format is exactly ROWS=<n>` | 契约·留 | 契约·留 ✓ |
| `Example: you must print ROWS=<n>` | 强制词·留 | 强制词·留 ✓ |
| `Read the file with print and show the shape.` | 契约·留 | 契约·留 ✓ |

**修法**：在契约检查**之前**判"这段是不是以示例/背景标记开头"，是则按 R1/R2 删；
但新增 `FORMAT_LOCKS`（`exactly` / `format is` / `must be` / `格式为` …）——
写了强格式声明的段即使以 `Example` 开头也保护。

**关键区分**：`output` 是"提到输出"（示例里常见，可删），`format is` 是"规定死了格式"（必须留）。

### 缺陷 B｜剪枝判据没有噪声带，导致**冗员永远删不掉**

`prune.analyze()` 的判据是：

```python
if g_short > 0:            # g_short = max(最近 n_prune 轮的 ΔS)
    productive              # 保留
```

`g_short` 取的是 **max**。所以只要窗口里混进**一个**正数噪声，就判"有产出"。

实测（6 轮 ΔS 在 ±0.03 抖动，**真实效应 = 0**）：

| δ | 判定 |
|---|---|
| 0（旧） | **productive（保留）** ✗ |
| 0.05 | candidates（待删）✓ |

**后果**：真实实验里 ΔS 一定有噪声，于是**几乎所有被编辑过的组件都会判 productive，
剪枝功能形同虚设**。

**修法**：加 `delta` 参数，两侧都留出噪声带：

```
g_short >  delta  → productive
g_long  <= -delta → confirmed
```

默认 `delta=0.0` **保持旧账本的分析结果不变**（向后兼容），新实验由
`cli prune --delta` 显式传实测值。

**这与 `gate` 用 `S*−δ` 是同一个道理**：两个判据必须用同一块地板。
在此之前，`gate` 有 δ、`prune` 没有 —— 那是第三处"判据不一致"。

## 五、这一轮的自我批判

1. **"不划算"这个判断，我说了三次**（jsonl、`_f`、`index_*`）。前两次真的不划算，
   第三次（`index_*`）我错了 —— 它一合并就 −16 行，因为两份是**骨架相同、只有一个字段差**，
   参数化几乎无成本。**我把"需要参数化"当成了"一定不划算"，没算具体数。**
2. **算法维度我完全没有主动审过**。前三轮全在看"结构重复"，那是**代码的形**；
   而 `R1` 永不触发、`prune` 无噪声带，是**代码的实**。形对了实错了，一样是坏的。
3. **最讽刺的一条**：我上一轮刚写"注释是判据不能压"，这一轮就发现
   `pass_rate_of` 的注释是编的、`R1` 的注释说"纯示例段可删"但实际永不触发。
   **注释写得好，不等于代码做得对。**
