## 二、修掉的第 4 个 bug：把 δ 调大能洗白掉分

这是这一轮**最有价值的东西**，比行数重要。

`prune-round` 原来的判据只有一行：

```python
verdict = "保留（删了会掉）" if d < -delta else "可删"
```

后果：**δ 是个可调参数，调大就能让掉分通过。**

| δ | 掉 50pp（1.0 → 0.5）的段 |
|---|---|
| 0.05 | 判「保留」✓ |
| **0.6** | **判「可删」** ✗ |

这正是老师点名要防的「**调低 δ = 用噪声换分数**」。而且它和 `run-m0` 的判定**直接冲突**：
同一个「删了掉 4pp」的改动，在 `run-m0` 里被地板拦住，在 `prune-round` 里会被接受。

**修法**：改走 `decide()`，用删除非对称通道 + 带内定价。

`band_score()` 对 dS 的系数是**不对称**的（`gate.py:111`）：

```
dS > 0 → 系数 0     带内涨分不给信用（RRSI 同款）
dS < 0 → 系数 1.0   掉分要全额算账
```

所以 δ=0.6 时掉 50pp：`-50pp`（掉分）+ `2.5pp`（K 降 25% × 0.10）→ **净 -47.5pp → 拒**。

**新增两条测试锁死这个行为**（`test_prune_round.py`）：

| 测试 | 断什么 |
|---|---|
| `test_delta_decides_which_branch_runs` | δ=0.05 走 `floor`；δ=0.6 走 `band` |
| `test_big_delta_does_not_launder_a_drop` | **δ=0.6 时掉 50pp 仍判「保留」** ← 旧代码会失败 |

把 10,446 行逻辑按"是什么"分一遍，剩下的都**不是重复，是不同职责**：

| 类别 | 量级 | 能不能合 |
|---|---|---|
| `RoundResult`（简化轮） vs `RoundReport`（演化轮） | 70 + 40 | **不能**：字段并集 30+ 个，合并后比任何一份都大（同 `Trial` 的教训） |

| 测试 6,300 行 | — | 是"改动是否安全"的唯一判据，不能删 |

**结论：在这个仓库里，「合并」的收益是「口径统一」，不是「行数减少」。**

两轮下来真实收获是：

| # | 修掉的 bug | 严重度 |

**四条都是"判据没生效"或"判据能被绕过"，没有一条是"代码多"。**

## 六、边界

1. **两个 CLI 入口保留**。`run-m0` 出三张表、`prune-round` 出逐段表，输出形态不同；
   底层已是同一份实现。合成一个命令就得加 `--mode` 参数——那是把复杂度从文件挪到参数，不划算。
2. **`counterfactual_prune` 的循环没并进 `run_m0_round`**。因为 `run_m0_round` 每次都重测
   baseline，逐段循环会重复测 N 次；而且 `drop_idx` 是**段落下标**、`prune-round` 是**小节标题**，
   两个粒度不匹配。硬并会引入一个转换层，比现在更绕。
3. **`prune-round` 的 `--auto`（规则出候选）没做**。它需要段级删测，与现有小节级是两套粒度，
   加上去是 +30 行而不是减。**先不做，等确认值得再说。**
4. **scripted 后端下所有段都判「可删」是替身局限**（它不看文本），`cmd_prune_round` 已有告警。
   这个结论不能当证据。
