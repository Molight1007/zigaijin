### 为什么会错这一半

两个技术原因，都值得记下来：

1. **证据源选错。** v1 只读了 `工具功能说明_20261102.docx`（39 条"能做什么"），
   而 `gate.py`（281 行）、`prune.py`（175 行）这些核心判据**根本不在那份说明里** ——

2. **检索关键词猜错。** 第一次查 K 时用 `K_|gzip|metrics|complexity` 当正则，

⇒ **纪律（写进本项目规矩）**：
对"某能力不存在"这类断言，必须同时满足三条才允许下：
① 读过度量该能力的模块源码；② 用过至少两种命名风格的检索（`dK`/`K_`/`k_rel`/`gzip`/`length`）；

## 一、仍然成立的 5 条

### 缺陷 1（致命）｜没有非反馈轮 —— 自压缩唯一的独立优势被丢了

**老师要求（3.4 / 3.5）**：
> "非反馈轮：没有外部反馈，只以演化集分数不显著下降为底线，并配合 ΔK 判据。
> 此时压缩完全依赖内生信号 —— **ΔK 可以即时计算，不需要任何外部打分**。"
>
> "除常规变异外，**每一轮额外执行一次纯压缩尝试**……在被外部反馈'遗弃'的轮次里，让 harness 继续变简洁。"

**源码事实**：全项目检索 `非反馈` / `pure_compress` / `纯压` —— **零命中**。
`run_m0_round()` 的每一步都要分数（`run_once` → 判分 → `gate`）。

**后果，且是当下正在发生的**：
工具说明自己写着"跑 Terminal-Bench ○ 卡在容器环境没起来"。
**容器起不来 ⇒ 没有分数 ⇒ 按现在的流程整个工具停摆。**
而老师理论在此处恰好给了出路，我们没接。

**补法（成本最低、价值最高）**：
工具已有 `sandbox_openhands.replay(ref, task)`（351 行），它就是"不重跑 agent、只重检产物"。
现在它**零调用**。接上它 + `metrics_pool.compare_text`，纯压步骤立刻可跑：

```
每轮末尾：挑一处措辞类冗余 → 删 → replay 重检（不烧 model）→ 分数不显著下降则采纳
```

零新 rollout。这也顺手把 `replay` 从"有接口没能力"变成"真在用"。

### 缺陷 2（致命）｜编辑空间锁在三样文本 —— 论文主贡献有一半在能力之外

**老师要求（1.2）**：
> "RRSI：**编辑空间保持完全开放**，约束只施加在'如何穿过这个空间'。"

**源码事实**：
```python
ALLOWED_FILES = ("SKILL.md", "variables.yaml", "rules.yaml")   # planner.py:53
FORBIDDEN_HINTS = {"sandbox_openhands.py": "判分器", "tasks/": "任务集",
                   "tests/": "测试代码", "evaluate.py": "分母口径"}   # 有测试断言
```

**为什么这条是致命而不是"高"**，看 `07_功能需求`：
> "删除有两条路线——静态死组件（地基）和**动态无用组件（要实验，是核心贡献）**。只做前者，论文不成立。"

而路线 B 要求"**逐段删掉，真跑一遍**"，F6 要出"保留 / 删除 / 不可判"三态表，
对象是**六类组件**（代码 / 工具 / middleware / 钩子 / 提示 / 编排）。

⇒ **工具能动的只有"提示 + 配置"两类。剩下四类诊断得出来但删不掉，F6 在它们上面无法执行。**

**但这里有一个现成的解药，而且它零引用**：
`src/adapters/harness_code.py`（180 行）就是"扫 agent 源码里的可编辑单元"的适配器，
`TARGET_KINDS = (control_flow, output_plumbing, context_mgmt, client_tool, memory, subagent)` ——
**正是 `ALLOWED_FILES` 缺的那几类。它写好了，只是没接进流程。**

**补法**：把 `harness_code` 接进 `planner`，`ALLOWED_FILES` 从"文件名白名单"升级为
"文件名 + 单元类型白名单"，先放 `skill/tool 描述`，再放单个工具函数，middleware 最后。
并在论文限制一节写明当前处在哪一阶段。

### 缺陷 3（高）｜提议侧不读账本 —— P2 只实现了选择侧

**老师要求（2.2(2)）**：
> "后续轮次的提议**以 L_t 为条件**：已被证伪的假设不再重复提出，有效的机制保留显式信用。"

**源码事实（两半，必须分开说）**：

| 侧 | 谁读账本 | 证据 |
|---|---|---|
| **选择侧** | ✅ 读了 | `cli.py:591` `analyze(Ledger(p).records(), n_prune=…)` —— prune 的收益窗口就是账本算的；`run_m0.py:256` 也读 |
| **提议侧** | ❌ 完全不读 | `planner.py` 全文**没有 ledger / history 任何字样**；`orchestrator.py:283` 构造 `Planner(llm, model=…, max_cards=…)`，不传历史 |

`Ledger` 本身能力齐全：`__iter__` / `records()` / `summary()`（含 `by_unit`、`units_touched`），
**问题不在账本，在提议侧没接**。

**后果**：每轮 `Planner` 从零生成任务卡，不知道上一轮试过什么、哪些假设已被证伪。
唯一的去重是 `Critic.check_batch` 的 `duplicate` 规则 —— 那只管**一次批量内**。

⇒ **老师 P2 的两半，我们只做了"用历史算剪枝"（P4），没做"用历史约束提议"（P2）。**

**补法**：`Planner` 增加 `history: list[DecisionRecord] | None` 参数，
生成卡片时把"已证伪假设 + 试过的 unit_id"作为负例注入 prompt。
同时用 `units_touched` 判断哪些组件从未被探过（接缺陷 4 的探索槽位）。

### 缺陷 4（中）｜编辑预算没有退火曲线，`b_t ≡ 3`

**老师要求（2.2(1)）**：
> `b_t` 从 `b_max=4` 单调降到 `b_min=1`，"后期轮次越来越稀疏，使'哪一处改动带来了提升'更容易归因"。

**源码事实**：`Critic(max_edits=3)`，常数。注释诚实地写着"受退火预算 b_t 约束（这里用 max_edits）"——
**是近似，不是实现**。

**后果**：后期仍允许一次捆三处，归因难度不降。叠加缺陷 3（提议侧不读账本），
"改了三处、涨了分、不知道哪处起作用、也没有历史可查"。

**补法（一行）**：`max_edits = max(b_min, round(b_max - (b_max-b_min)*t/(T-1)))`，
`t` 从 `Ledger.summary()["n"]` 取（现成的）。既用了账本，也把常数变成了曲线。

### 缺陷 5（中）｜critic 有 8 条规则，缺 3 类语义审查

**已实现**（`critic.py`）：白名单 / 分档（A 档才可自动改）/ 值域 / 接线（死配置拒）/
泄漏（8 条正则：题号、题库路径、判分器、gold）/ 删除安全（必须写回滚方式）/
批量上限 / 重复改同一单元。

**缺的 3 类**（老师 2.3 第二层）：

| 类别 | 老师原话 | 现状 | 能不能机械判 |
|---|---|---|---|
| 退化 | "名为机制实为空操作；或移除、禁用既有安全机制而不提供等效替代" | 无 | 半可判：新值 == 旧值、删了 if 判断但未加替代 |
| 运行期记忆泄漏 | "新增的记忆或技能机制在试验之间持久化状态" | 无 | 可判：diff 里出现全局 mutable / 文件写入 / cache 写入 |
| 无界工作量 | "新增没有退出路径的检查、重试或持续改进循环" | 无（只有外部调用上限） | 可判：AST 找新增 while/retry 是否有可达 break/上限常量 |

**注意**：现有 8 条里没有一条覆盖"未申报捆绑"——但有 `batch_size`（总量上限）
与 `duplicate`（同一单元重复），能覆盖一部分。老师原意是"申报了一处、实际改了三处"，
这个要**比对申报范围与实际 diff**，现在两边是同一份数据，无从比对。

## 三、先说四条它做对了（不该在改的过程中被抹掉）

### ① 状态标注本身就是方法论

工具说明开头写"✅ 真的跑过｜○ 代码写好了但没跑过"。一篇技术文档肯把"没跑过"标出来，
比多数论文附录诚实。**而且这份批判能成立，全靠这个标注** —— 同样的批判放到一篇全绿的说明上就无从下口。

### ② "未验证记未知"比 RRSI 的"记负证据"更细

工具说明第五节第 3 条：**"没验证过的记成「未知」，不写成 0 分"**。

老师文档 2.3 的规则是：修不好的候选"作为'无测量结果'的负证据记入历史"。
两者不同，而且**我们对**：

| 测不出来的原因 | RRSI | 我们 | 谁对 |
|---|---|---|---|
| 候选本身不可测（无界循环跑不完） | 负证据 | 未知 | RRSI |
| 评测设施故障（TB2 容器没起来） | 负证据 | 未知 | **我们** |

把"设施坏了"记成"候选坏"，会让 L_t 学到假规律。这条细分可以写进论文当贡献。

### ③ "说不清为什么不用更省事的办法"就拒 —— RRSI 没有

工具说明第三节第 6 条：**"空话方案直接拒：说不出为什么不能用更省事的办法、写不出生效条件、写不出怎么验证"**。

老师文档 2.3 的六类拒绝里**没有这一条**。我们额外要求**自证最小性** + **可证伪** + **可验证**，
合起来是一道"反懒惰闸门"，直接压制 RRSI 最容易出的退化 —— **用新增机制代替修逻辑**。

### ④ 判据里写的调参理由，是论文最缺的东西

`kappa1` 从 5.0 收到 0.5 时，注释写了"原值同样没有出处（当时随手写的）"；
`pp_per_*` 的注释写"这是人为定价，不是实测——报告里必须声明，并用敏感性分析兜底"。

⇒ 这种"我知道这个数是拍的"的自我标注，比任何漂亮的结果都值钱。

## 四、反向批判：老师理论在我们场景下的三处不适用

### A. 无损压缩字节数可被"改名"套利

K(h) = 全量文本 gzip 后的字节数。老师 3.2 第三类算子明确允许"用更短的等价表示替换原有长表述"。

于是最优策略是**把长标识符改成短名字**：`capability_registry_for_tool_invocation` → `a`，
K 立刻降，行为完全不变。这不是假设，是**优化器的必然解**。

⇒ 需要配"可读性下限"（标识符长度分布 / 命名白名单 / 最小 token 数），并把豁免量记账。

### B. 行为等价不可判定时，"不显著下降"是弱证据

老师文档 六 自己写了："若行为等价性无法判定，压缩就可能误删必要能力。"
而 3.4 给的授权依据是"行为分不显著下降" —— **分数是采样估计，功效有限**。
工具自己也承认"n=10 只能检测 ≥10% 的失败率"。

⇒ 用低功效检验得出"没变"、再用"没变"授权**不可逆**的删除。两条收紧：
① 删除类要求单侧检验 + 功效预先声明；② 只对**措辞类**放行"不显著即删"，机制类必须显著不降。

### C. 压缩算子与"改写不算删"的口径冲突

老师 3.2 第二类算子"合并等价表述：把分散在多处的同一规则归并为一条定义，其余处改为引用"。
按老师口径这只是 `ΔK`（净变化），按我们 `00_总纲` 的口径"改写（replace）不算删"，合并会记成 0 删除量。

⇒ 两套口径必须选一个当主口径。建议：**主口径 ΔK（净字节）**，因为它可复算；
"删除覆盖率"降为**过程诊断指标**，只解释"K 为什么降"，不用于判定。

## 六、这份批判的边界

1. **只核了判据层**（gate / critic / prune / ledger / planner / metrics_pool），
   adapter 层与 `run_m0` 的细节没有逐行读。
2. **"不成立"只在"我搜过的地方"成立**。每条撤回都写了源码行号，可以直接复核；
   反过来，如果哪条我给不出行号，就说明我没核到。
3. **v1 的错误不是笔误，是方法错误**：拿通俗说明当唯一证据。这条比任何结论都值得记住。
4. **同一个错误犯了三次**：查 `gate` 时搜 `K_`（代码叫 `dK`）、查 `Ledger` 时搜 `load`（方法叫 `records`）、
   查 `planner` 时搜 `sort`（实际是 LLM 输出的 `priority`）。
   ⇒ **"没搜到"永远不等于"不存在"**，只等于"这次检索没命中"。下次先 `grep -n "def " 文件` 列出全部方法名再判断。
