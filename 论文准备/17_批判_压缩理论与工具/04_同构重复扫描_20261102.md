# 04 同构重复全量扫描 —— 找"同一件事写了两遍"

> **一句话：677 个函数两两比了 228,826 对，命中 32 对同构候选；
> 其中真重复 3 类、合法相似 5 类。真重复全是"小而散"，唯一的大块是 `run_m0` ↔ `evolve_round`。**

起因：`run_m0` 与 `evolve_round` 是同一个流程的两个实现，我起初没认出来（见 `03_判断错误记录.md`）。
于是用同一判据扫全仓库，看还有没有同类型的坑。

---

## 一、扫描方法

三条判据，任一命中即列为候选（对应 `03` 第三节）：

| 判据 | 怎么算 | 为什么有效 |
|---|---|---|
| **签名同形** | 参数名集合的 Jaccard | 同一件事往往用同样的入参（`tasks, n, text`） |
| **调用序列同序** | 函数体内被调名字集合的 Jaccard ≥ 0.6 | 同一件事会调同一批函数 |
| **类字段同构** | dataclass 字段名 Jaccard | 同一个概念被建模了两遍 |

规模：`src/` 非测试 677 个函数 / 228,826 对。

## 二、真重复（3 类）

### 2.1 读 jsonl 的 6 处 —— 不合并

| 位置 | 行数 |
|---|---|
| `domain/observability.py:all_traces` | 5 |
| `domain/security.py:records` | 5 |
| `adapters/feedback_file.py:_rows` | 14 |
| `domain/dataset.py:load` | 5 |
| `domain/report.py:_load_ledger` | 9 |
| `usecases/run_index.py:read_index` | 9 |

调用序列 Jaccard：`security.records` ↔ `observability.all_traces` = **1.00**（完全一致）。

**判定：不合并。** 6 处合计 47 行，抽公共函数约 10 行，净省 37 行 —— 但那个公共函数**没有合适的家**：
放 `domain/` 要为它新建模块（+20 行样板），放任何一个现有模块都会让那个模块职责变浑。
**净省 37 → 实际 17 行，代价是新增一个"通用 IO"模块。**

⇒ 这正是 `01` 里 E-note 说的：**小规模重复（<10 行）归一，成本常大于重复本身。**

### 2.2 `_f` / `_f` / `_get` 三处 —— 不合并（同上理由）

```python
# domain/prune.py:33          domain/simplify_guard.py:?      domain/llm_metrics.py:?
def _f(rec, key, default=None):  def _f(c, key, default=None):  def _get(obj, key, default=None):
    if isinstance(rec, dict):        if isinstance(c, dict):        if obj is None: return default
        return rec.get(...)              return c.get(...)          if isinstance(obj, dict): ...
    return getattr(rec, key, default)  return getattr(...)        return getattr(obj, key, default)
```

三份语义等价（`getattr(None, k, d)` 本就返回 `d`，所以 `_get` 的 None 分支是冗余的防御）。
**净省 10 行，不够一个公共模块的样板钱。**

### 2.3 同文件内的两对 —— 该合并，但收益 30 行

| 对 | 行数 | 调用序列 |
|---|---|---|
| `ledger.make_record` ↔ `ledger.make_unevaluated_record` | 19 / 30 | 0.75 |
| `harness_index.index_variables` ↔ `harness_index.index_rules` | 43 / 25 | **1.00** |

`index_variables` 与 `index_rules` 的调用序列**完全一致**（`Path/read_text/safe_load/isinstance/append/get/is_file/str`），
差别只在读哪个文件、抽哪个字段。合并成一个 `index_yaml(path, keys)` 可省约 30 行。

**判定：值得做，但优先级低于 `run_m0` 退役**（后者 686 行）。

## 三、合法相似（5 类，不该动）

| 类 | 例子 | 为什么不是重复 |
|---|---|---|
| Protocol 声明 vs 实现 | `ports/*.replay` ↔ `adapters/*.replay` | 契约与实现，本来就两份 |
| 同类多实例的序列化 | `to_dict` × 6 | 每个类的输出结构不同 |
| 同类多实例的初始化 | `__init__` × 4 | 各自校验不同的东西 |
| 同族判据 | `detector._find_unused_imports` / `_find_constant_conditions` / `_find_unreachable` | 都产出 `Candidate`，但**判据不同**——这是设计 |
| 上下游而非重复 | `noise_band`（算带）↔ `estimate_delta`（估带） | 一个用结果、一个产结果 |

⇒ **反判据**：两个东西长得像，但"删掉一个，另一个承担不了它的职责"，就不该合并。

## 四点五、判定板块：三处 → 一处（本轮最大收获）

用**另一条扫描方法**发现的（相似度扫不到，因为三处调用序列不同）：
**`grep -rn "gate(" src/`** —— 核心判据的多个调用点，就是重复判定的嫌疑。

| # | 位置 | 原实现 |
|---|---|---|
| 1 | `usecases/run_m0.py` | 自己组装 S*/CI/δ，直接调 `gate` |
| 2 | `usecases/orchestrator.py` | 只报 `pass_rate`，不判 |
| 3 | `usecases/experiment.py` | 自己调 `gate`，star/cfg 由外部传 |

现在统一为 `domain/judge.decide()`：S* 从账本取、地板、成本门、ΔK 预算、带内整形、
配对 CI 全在一处；三个调用方只负责准备材料。

收益不在行数（新增 `judge.py` 86 行，K 反而 +1.1%），在于**口径不再漂**：
此前 `run_m0` 的 δ 是实测、`experiment` 的 δ 由调用方传、`orchestrator` 根本没有 δ。

## 五、结论

**这个仓库的重复是"小而散"，不是"大而整"。** 32 对候选里：
- 3 对是"同一个东西写两遍"，但都 <50 行
- 剩下的要么是契约与实现，要么是不同判据的同族函数

唯一符合"大块重复"特征的，**就 `run_m0` ↔ `evolve_round` 这一对** —— 也正是我一开始没认出来的那一对。

⇒ 这条经验值得记：**量大 ≠ 重复。真正的重复看"职责能否互换"，不看行数。**
反过来也成立：**行数少的重复同样该修**（`delta_*` 那 12 行就是，因为它和 `gate._rel` 是同一逻辑的两份实现，
改一处漏一处）。
