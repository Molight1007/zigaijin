## 一、合并前的真实结构：三层重复，不是两个文件

上一次汇报说"run_m0 与 orchestrator 各自实现了一遍评测器"。核实后**比这更严重**：
重复有三层，每层的份数不同。

| 层 | 合并前 | 合并后 |
|---|---|---|
| **类型**：一次试验的记录 | **3 份**，字段互不兼容 | `domain/trial.py::Trial` **1 份** |
| **评测**：跑一版文本 n 次 | **2 份**，能力互补但不重叠 | `usecases/evaluator.py::evaluate_text` **1 份** |
| **聚合**：trial 列表 → Score | **3 份**，口径不同 | `domain/evaluate.py::aggregate` **1 份** |

### 1.1 三份 Trial 的字段差异（这是 bug 的根源）

| 字段 | `run_m0.TrialOutcome` | `orchestrator.TrialRecord` | `run_index.TrialRecord` |
|---|---|---|---|
| `task_id` / `rep` / `passed` / `run_dir` | ✅ | ✅ | ✅ |
| `version` | ✅ | ❌ | ✅ |
| `output` / `error` | ✅ | ❌ | `error` ✅ |
| `cost` / `cost_usd` | `cost_usd` | `cost` | ❌ |
| `tokens` | ✅ | ❌ | ❌ |
| **`missing`** | **❌** | ✅ | ❌ |
| `session_id` | ❌ | ❌ | ✅ |
| `checks` / `digest` / `trace` | ❌ | ✅ | `checks` ✅ |

**各自缺的字段，恰好是别人算分要用的。** 所以不是"多写了几行"，是三个量算不出来：
`missing_rate`、`cost`、`pass^k`。

### 1.2 三份聚合的口径差异（这是 bug 的直接原因）

| 实现 | `n_expected` | `missing` | `pass_k` |
|---|---|---|---|
| `domain/evaluate.evaluate()` | `题数 × k` | **真实统计** | 同题 k 次全过 |
| `run_m0._to_score()` | `len(rows)` | **写死 0** | 全过 1 否则 0 |
| `orchestrator.judge_round.sc()` | **写死 1** | **写死 0** | = `S` |

只有 `evaluate()` 是对的，而它当时**只有 `experiment.py` 一个调用方**。

## 二、修掉的 3 个真 bug

### bug 1｜「缺失率 > 15% 整轮无效」从来没触发过

```python
# gate.py:166（合并前）
if cand.missing_rate > cfg.missing_limit:
    return _v(False, "behavior", f"缺失率 …，整轮无效")
```

`missing_rate = missing / n_expected`。而三份聚合里有两份把 `missing` 填成 0、
第三份把 `n_expected` 填成 1 —— **分子恒为 0，这条判据永远不成立**。

后果：一轮评测里崩掉一半 trial，只要通过率没掉，gate 照样接受。
`missing` 记 0 的同时，崩掉的 trial 又被当成"答错了"计入 S 的分母，
于是**"设施坏了"和"能力不行"混成同一个数字**。

**修法**：`aggregate()` 走 `evaluate()` 的真实统计，`Trial` 补上 `missing` 字段，
`_verify` / `stage1` 把 `missing` 一路带上来。

### bug 2｜缺失率超限被归到 `behavior` 分支

修好 bug 1 之后第一次有测试打到这条路径，才发现分支名是 `behavior`。
但 `behavior` 的含义是"G1 行为检查未过 = agent 做错了"，而缺失率超限是
"这一轮根本没跑起来（环境/超时/会话异常）"。

两者混在一个分支，账本统计"拒绝原因分布"时会把**设施问题记成能力问题**——
正好违反本项目那条"要区分'设施坏了'和'候选不可测'"。

**修法**：独立分支 `"missing"`。

### bug 3｜`run_m0` 的 legacy 分支 NameError（上一轮已修，此处补记）

账本写入段在 `if gate_mode` 外面，但 `cur_s` / `cand_s` 只在 `else` 里定义。
legacy 模式 + 传了 ledger ⇒ `NameError`。

### 附带修掉的两处

| 位置 | 问题 |
|---|---|
| `orchestrator.RoundReport.to_dict()` | `verified["trials"]` 是 Trial 对象，`json.dumps` 直接崩（`TypeError: Object of type Trial is not JSON serializable`） |
| `run_m0.RoundResult.to_dict()` | 用 `asdict(t)`，把 `trace` 原文（几千字/条）一起写进 round.json |

## 三、合并后的结构

```
domain/trial.py        Trial（三份并集）+ adapt()（RunResult / 鸭子类型 → Trial）
                      Trial.reward 属性让它直接满足 evaluate() 的 RunResult 协议
   ↓
domain/evaluate.py     aggregate(trials, n_tasks?, k?)   ← 唯一聚合入口
   ↓
usecases/evaluator.py  evaluate_text(run_once, text, n, tasks?, critic?, sample_pool?, render?)
                      precheck(critic, {label: text})   ← 多版一起筛，被拦就一次都不跑
   ↓
run_m0.run_m0_round    ← 旧流程：规则删段做候选
orchestrator.evolve_round ← 新流程：LLM 按失败改做候选
```

**两条流程现在共用同一份评测器、同一份聚合、同一个 `Trial`、同一个 `decide()`。**
差别只剩"候选从哪来"——那是两条不同的生成路径，不是重复。

### 3.1 合并后两边各自获得的能力

| 能力 | 合并前属于 | 现在 |
|---|---|---|
| 评测前泄漏预筛（T3） | 只有 run_m0 | **两边都有**（`evaluate_text(critic=…)`） |
| 失败样本入池（A4） | 只有 run_m0 | **两边都能用**（`evaluate_text(sample_pool=…)`） |
| 轨迹抽取 | 只有 orchestrator | **两边都能用**（`evaluate_text(render=…)`） |
| `missing` 标记 | 只有 orchestrator | **两边都有** |
| 配对 CI | 只有 run_m0 | **两边都有**（`judge_round` 补算） |
| `pass^k` | 只有 experiment | **两边都有** |

## 七、边界（这次没做的）

1. **`run_m0.py` 没删**。它是旧流程的入口，仍占 602 行。现在它与新版共用评测/聚合/判定，
   只剩"规则删段"这一条候选生成路径是它独有的。删不删取决于一个决策：
   **论文里还要不要"规则删段"这个零成本 baseline**。
2. **`pipeline` / `orchestrator` 仍无 CLI 入口**。`evolve_round` 只能靠测试或脚本驱动，
   `cli run-m0` 仍是唯一能一键跑的实验命令。
3. **K 涨了 1.26%，我没有为此压注释**。这次的注释是判据（"为什么这样合并""缺这条会怎样"），
   压掉等于把结论变回口头约定。
4. **`prune-round` 把 `Output` 段判成"可删"是替身局限**：scripted runner 不看提示词内容，
   恒定通过。真实 openhands 下含"must be exactly"的段会掉分。**这个数字不能当证据。**
